# 拼图管理工作台

本地项目位于 `D:/chat/拼图/content-admin`，入口为 [相册工作台](http://127.0.0.1:3214/)。用相册统一整理图片：每个相册就是一个图鉴；开启「购买包」后，同一个相册也作为收费图包。PC 与小程序共用一套相册，只在相册设置中选择在哪一端显示。

Web 与小程序的正式内容同步已接入，后台保存后可通过「提交到双端」发布运营设置。图片资源随同一次提交增量上传到服务器共享资源目录；程序代码和界面改动仍另行部署。统一配置、两端区别与提交流程见 [双端同步接入](docs/2026-10-13-双端同步接入.md)，图片上传机制见 [提交时上传图片](docs/2026-10-17-图片上传与交付.md)。

## 启动与登录

需要本机现有 Node.js 24，无需安装依赖。运行 `start.ps1`，再打开本地入口；也可在本目录运行 `npm start`。`stop.ps1` 只停止本工具记录的后台进程。

已有管理员继续使用原账号登录。首次访问才需要创建独立内容管理员，用户名 2–40 字符，密码 10–128 字符；没有默认密码或公开注册。内容管理员与游戏玩家账号独立，本版不提供邮件找回。

## 平时怎么用

只维护一份「当前工作内容」，日常整理不需要选择、创建或切换草稿。主界面有五个入口：

| 页签 | 用途 |
| --- | --- |
| 相册与未分配 | 同屏查看相册和未分配图片，直接拖动分配；点击相册进入内部图片查看与整理 |
| 全部图片 | 查看所有素材，按画风和题材筛选、编辑标签、选择图片放入相册 |
| 任务奖励 | 设置五项合作与好友任务、分享邀请、邀请好友和十格小礼共八项奖励的金币、经验与小程序体力，使用独立保存按钮 |
| 成长与体力 | 设置等级经验、体力上限、消耗、恢复、升级补充方式与完图体力，实时预览前 20 级 |
| 装饰与收集 | 设置金币、碎片与图鉴收录条件，管理现有装饰的名称、颜色、图案和合成费用；相册集齐奖励在各相册设置中调整 |

在「相册与未分配」页，把未分配图片拖到目标相册卡片，即可加入相册；也可先多选，再拖动其中一张，把所选图片一起放入。电脑宽屏采用左右排列，窄屏相册固定在图片上方。无法方便拖动时，继续使用多选后的「放入相册」按钮。顶部不再切换 PC 或小程序内容。

点击相册卡片进入内部图片页，查看成员、调整顺序、加入或移出图片。每张图片只能属于一个相册；加入另一相册时会移动原归属。名称、封面、成员、顺序、购买价格和奖励共用，整理一次就同时更新两端的内容规划。

相册卡片上的「设置」打开独立弹窗，不影响当前图片浏览位置。弹窗集中控制以下设置：

- **名称、说明与画风**：整理相册基本信息，已有名称会保留。
- **在 PC 显示、在小程序显示**：两项独立勾选。都勾选则两端显示，只勾选一项则只在对应端显示，都不勾选则两端隐藏。
- **购买包**：关闭时为免费相册，价格为 0；开启时设置至少 1 金币的整数价格。
- **封面**：从相册成员中选择；相册成员和图片顺序也是图鉴的成员和顺序。
- **相册集齐奖励**：在本相册里增加奖励档位，逐档设置集齐张数、金币和赠送装饰。免费与购买相册都可设置；所有现有装饰均可选择。

未分配到相册的图片仍可在后台查看和打标签，默认不纳入普通图库与相册图鉴规划。移出相册会取消共用归属，原件与稳定图片 ID 保留。隐藏相册中的图片仍属于原相册，不会重新出现在「未分配」中。每日拼图通过独立入口展示，采用下面的首发与候选池规则。

画风作为主分组，题材作为图片标签；两者用于查找和整理。多选图片后，底部操作栏可放入相册、移出相册，以及批量设置画风或题材标签。拖动与批量整理完成后点击顶部「保存」。相册弹窗的「保存相册设置」直接写入后台，同时保存本页已调整的图片归属与顺序。未保存的相册整理会在本机暂存，重新打开时可恢复；不同窗口的恢复记录分别保留。

## 图片压缩与流量

新图片默认生成保持原尺寸的 WebP Q70，采用 effort6 与 smartSubsample 编码；总像素不超过 6,553,600（约等于 2560×2560）时不因长边单独缩小，超过上限才按比例缩小。列表继续使用最大480×384的独立缩略图。原始 PNG 和已有无损版本保留。Q70是编码参数，不代表只保留70%的清晰度，文件大小随图片尺寸与内容变化，不强制每张固定KB。

已有Q84/Q88图片继续使用原交付文件，日常保存或「提交到双端」不会重新压缩图片。新默认用于之后的离线图片处理；调整现有线上图片需另行从PNG原图制作交付版本并上线，不能对旧有损WebP反复压缩。详细范围见[图片压缩标准](docs/2026-10-15-图片压缩标准.md)。

## 删除与恢复图片

图片详情可点击「删除图片」；全部图片、未分配图片或相册内部多选后可批量删除。确认窗会列出受影响相册和每日首发安排。删除会移出相册、替换失效封面并取消尚未出场的安排；已确认的每日出场记录保留，删除期间停止自动收录。图片从普通列表和选图器隐藏，在「全部图片 → 回收站」或「更多 → 图片回收站」恢复。

这是可恢复的删除：保留原件、稳定图片 ID、旧房间及玩家历史记录，不释放服务器图片存储。恢复后可重新放入相册；已出场但尚未收录的每日图片恢复后继续原收录安排。删除和恢复都先保存，再由管理员「提交到双端」生效，当日已经选中的每日图片仍保留到当天结束。相册成员变化会改变相册当前完成数量，已经发放的奖励与单张图片完成记录保留。

## 任务奖励

进入顶部「任务奖励」，五个合作与好友任务、分享邀请、邀请好友和十格小礼共八处都可设置金币和经验。五项任务与分享邀请还可设置小程序体力；邀请好友礼包在小程序补满当前体力；十格小礼可设置三个等级段的体力范围。分享邀请的每日奖励次数可单独调整。任务目标、每日领取身份和好友资格规则保留。

两端共用同一份任务奖励，Web 跳过体力字段，不显示、不消耗也不发放体力；金币、经验与小程序采用相同数值。旧奖励配置没有金币字段时按 0 读取，保留原体力和经验，不因读取改写已保存数据。

点击「保存任务奖励」独立保存，用于后台编辑和已接入的本地预览，不影响相册或图片的未保存编辑。正式生效使用顶部「提交到双端」流程。新配置只影响之后新发放的奖励，已存礼包按原快照开启，已领取任务不会重复发奖。完整说明见 [任务奖励管理](docs/2026-10-13-任务奖励管理.md)。

## 成长、体力与装饰

「成长与体力」和「装饰与收集」使用同一份游戏设置。可以先在两页分别修改，再点击「保存游戏设置」一起保存；相册和任务奖励仍各自保存。默认数值沿用当前规则，新增设置不会替玩家清零或重算等级。

已有等级、经验、奖励余额与装饰持有记录保留。修改经验门槛后，下一次获得经验按新门槛继续升级；初始体力只用于之后创建的新玩家。已经发放的礼包按原数值开启。相册各档金币和赠送装饰在对应相册设置中修改，原领取记录保留，同一档不会重复发放。关闭装饰的商店展示会停止新合成，已有装饰仍可装备，图鉴装饰奖励继续发放。

保存用于已接入的本地预览；通过顶部「提交到双端」发布到正式环境。Web 使用共用成长与收集配置中的相关规则，跳过体力系统。完整说明见 [成长与装饰管理](docs/2026-10-13-成长体力与装饰管理.md)。

## 保存与游戏生效

日常可以按「修改 → 保存 → 提交到双端 → 检查范围 → 确认提交」操作。提交的是全部已保存的运营设置：相册及奖励、每日图计划、任务奖励、成长体力和装饰收集，也包括其他页面先前保存的改动；不是只提交最后编辑的页面。未保存编辑或预览后又有变化，会要求先保存或重新准备。

发布包含四份设置文档、图片资源索引和版本校验信息，不包含游戏源码、界面程序、新特效、玩家数据库或账号信息。新图片会随本次提交增量上传到服务器共享资源目录，两端重启后即被识别；未上传成功的图片会留在后台并在预览提示。最近的光标位置、装饰样式退役和新版入口调整属于程序变更，仅点内容提交不能让这些程序改动上线。原有玩家数据和已发礼包不会被运营设置覆盖。

**保存用于后台编辑与本地预览，正式生效使用顶部「提交到双端」。** 相册、每日安排、任务奖励和游戏设置各自保存；提交使用这些已保存内容，页面上未保存的输入不会进入正式版本。相册成员、显隐、购买价格与每档奖励保存在独立相册配置中，设置见 [相册独立奖励](docs/2026-10-13-相册独立奖励.md)。

Web 与小程序分别校验通过后，使用同一个完整版本。预览后若又保存了新修改，需要重新预览。只有成功提交才更新正式配置，单纯保存不会自动上线。协议和进度见 [双端同步接入](docs/2026-10-13-双端同步接入.md)。

图片可在后台按画风整理，历史明细见 [图片相册整理记录](docs/2026-10-12-图片相册整理.md)。当前图片数量和交付状态以后台与提交预览为准。标记「待接入游戏」的图片可以分配相册、选择封面和设置购买，但这些操作不会上传缺少的资源文件；资源交付后才能实际进入游戏。

2026-10-17 新增《猫咪漫游记》相册，含六张猫咪插画和如实标注来源尺寸的3840×3840放大版，已完成后台入库及双端资源交付。相册展示等运营设置仍由管理员「提交到双端」确认生效；「提交到双端」现已支持随配置上传新图片，见 [提交时上传图片](docs/2026-10-17-图片上传与交付.md)。

图片详情勾选「安排每日首发并自动收录」后，默认勾选「自动发布」，并启用收录相册选择。自动发布只加入候选池，不预先占日期；取消自动发布后，才手动指定首发日期。每天先使用当天的手动排期；当天没有排期时，随机选一张尚未发布的自动发布图片；候选池用完后，从所有相册中已有游戏资源的图片随机选一张，包含购买相册和隐藏相册，未分配图片不参加这层随机。每日入口创建公开房间无需解锁图包，也不扣建房券，原有房间数量限制仍生效。

每天首次实际生效后锁定当天图片，刷新与修改未来计划不会换图。安排首发的图片实际出现后，于次日北京时间 00:00 自动归入预选相册；从已有相册随机推荐的图片保留原归属。后台保存计划不算出场，未交付的图片也不会提前进入实际候选池。启动本地小游戏预览时，如果后台公开配置已生成，会自动接入；正式环境统一通过顶部提交。完整规则见 [每日拼图收录说明](docs/2026-10-12-每日拼图收录方案.md)。

主界面不再分别维护图包与图鉴，也没有单张图片的上架或图库显隐开关。图包、图鉴和普通图库归属统一从相册规划推导。

## 更多：历史、完整备份与更新文件

顶部「更多 → 历史与备份」只用于内容备份、恢复和旧版更新文件导出，不是新的双端正式提交入口。以前的草稿副本作为只读历史查看，日常继续操作当前内容即可。

可检查已保存改动、保存共用相册的完整内容备份，或下载历史备份。恢复备份会成为当前工作内容，不要求再选另一份草稿。保存完整备份、恢复和来源同步需要填写原因并再次验证管理员密码。

「准备更新文件」保留旧版导出功能，可选择文件接收应用；这不是另一套可编辑内容，也不等于提交正式配置。只有所选应用兼容检查通过时才可生成；有待解决的问题仍可保存整理结果和完整备份。旧运行时未接入的规则会明确提示并阻止生成不兼容文件。导出文件供旧发布流程审阅、接入和发布，生成本身不会替换游戏源码或上线；新的统一提交流程使用顶部「提交到双端」。

来源同步会合并当前整理与原项目的独立改动；同一字段同时被修改时保留编辑并报告冲突，避免静默覆盖。

## 数据保管与验证

后台只读两个游戏项目，写入保存在自身 `work/` 私有目录。目录含管理员密码摘要、会话、当前内容、备份与审计，已忽略版本控制，不能放进公开静态资源目录。停止后台后复制整个 `work/` 可保留完整本地数据；运行期间不要随意替换 SQLite 文件及 WAL。内容备份恢复不涉及玩家数据库。

生成游戏更新文件时复用已有来源、审核、原件、WebP 交付与资源清单校验，不输出原件、密钥、数据库或玩家档案。历史图片 ID、已购权益、奖励、每日轮转与旧房间资源仍受保护。

聚焦检查使用 `npm test`；测试采用独立临时后台，不写真实游戏或正式管理数据。此前相册模型已通过 19 项聚焦验证。当前方案见 [PC 与小程序共用相册记录](docs/2026-10-12-PC小程序共用相册.md)。历史演进见 [相册工作台记录](docs/2026-10-12-相册工作台.md)、[相册拖动整理记录](docs/2026-10-12-相册拖动整理.md)；新图保管记录见 [新图导入记录](docs/2026-10-12-new-art-import.md)。
