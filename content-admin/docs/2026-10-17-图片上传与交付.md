# 提交时上传图片

2026-10-17。此前「提交到双端」只上传四份运营配置，新图片必须另行交付到服务器运行包，否则无法勾选进相册。
本批改动把图片资源做成与配置同时提交的一层：后台增量上传缺失文件，两端运行时从共享资源目录读取图库。

## 之前为什么传不了

两端把图片清单编译进程序包：Web 的 `server/managed-content.node.mjs` 静态 import `content/puzzle-catalog.json`，
小程序后端把同一份清单打包进 `outputs/mobile/engine.mjs`。改图库就等于重建、重传整个运行包（各约 1.1 GB），
所以后台按钮只能提交 JSON 配置。另外 Web 的静态文件由 vinext 的启动期文件缓存提供，新文件不重启不生效。

## 现在的结构

服务器共享资源目录，与配置发布目录并列、互不影响：

```
/srv/sites/jigsaw-content/assets/
  catalog.json      图库（与本地 content/puzzle-catalog.json 逐字一致）
  guidance.json     实测尺寸
  puzzles/          交付图片：play / thumbnail / optimized 三种 WebP
  tools/            apply-assets.py 交付脚本
  receipts/         每批回执
  .incoming/        上传中转（处理完即删）
```

- 两端运行时优先读该目录（`JIGSAW_ASSET_CATALOG_DIR`，默认此路径），文件缺失或损坏时回退到编译进包的内置清单。
  因此后台传新图库后重启服务即生效，不需要重建运行包。
- 静态文件由 nginx 直出共享目录，不再依赖构建期清单：
  `/puzzles/` → `assets/puzzles/`，`/h5-mobile-v3/assets/puzzles/` → 同一目录。
  两端静态路径同时保留硬链接（Web `dist/client/puzzles`、小程序 `public/puzzles`），应用自身读文件的校验仍然通过。

## 后台怎么用

「提交到双端」预览新增图片区块：

- **图片资源已就绪**：本地图库的每个文件服务器都有，无需上传。
- **需要上传图片**：列出缺失文件数量与体积，可点「立即上传」单独补图。
- 点「确认提交」时，若仍有缺失会自动先上传图片，再发布运营设置；上传失败则停在失败提示，配置不会被发布。

上传只发送缺失文件（按 URL 去重），已是同一份字节的不重复上传。每批回执写入 `work/asset-uploads.json`，
成功上传的图片同时登记到 `work/delivered-assets.json`，后台预览不再把它算作「未交付」。

## 安全与校验

- 只允许 `/puzzles/` 下的文件名，路径中不允许目录分隔符。
- 每个文件上传前核对本地大小与 SHA-256，服务器端再次核对后才落盘；同名不同字节一律拒绝，不做覆盖。
- 原件 PNG 不上传（运行时 `src` 已替换为压缩版），只传 play / thumbnail / optimized。
- 上传后重启 Web 与小程序服务，回执记录每个文件在两端是 link 还是 copy。
- 不传源码、私钥、玩家数据库。

## 已知边界

- 新图仍要先进图库（导入步骤生成 WebP 与登记），本功能负责「已入库 → 上线」这一段。
- 图片需要加入相册才会出现在玩家端；上传本身不上架。
- 每次图片变更会重启两端服务（约 1–2 秒中断），没有做热加载。

## 第二步：美术版本登记也数据化（2026-10-17 23:00）

上传完成后发现一个漏项：图库能读了，但**开房要用的图片版本登记**（`artwork-revisions`）仍编译在程序包里。
新图片能进相册、能被图库识别，玩家点「开始拼」却会报 `图片版本尚未完成交付登记`。

改动（两端各一处逻辑，接口不变）：

- 房间画质登记表里查不到这张图时，不再直接抛错，而是用图片自己的登记文件与实测尺寸生成一份快照：
  `revision` 取压缩版的 URL（文件名自带内容摘要），宽高取图库记录。同一张图永远得到同一份快照。
- 客户端收到服务端写进房间的 `artwork` 快照时，本地登记表里没有也接受（服务端只会写来自图库的数据），
  只校验结构与本域名路径，防止拼出外部链接。
- 大厅卡片与房间页面在没有编译期记录时，改用服务端下发的缩略图与画面尺寸渲染，不再白屏。

部署：

## 关于「打包」的现状

| 改动类型 | 现在要不要打包 |
| --- | --- |
| 加图片（改图库、尺寸、美术登记） | 不用。传文件 + 更新共享目录，重启即生效 |
| 改相册、每日、任务、成长、装饰 | 不用。已经是发布配置 |
| 改界面、玩法、渲染逻辑 | 要。Web 前后端都要重新构建，小程序客户端需要更新包 |

客户端包里仍然带着全量图库（14 个组件直接 import），所以图片一多，JS 会变大。这不影响「加图不打包」，
只影响首包体积；TapTap 负责首包分发且限 60MB，当前 JS 部分约 6MB，暂不需要处理。
