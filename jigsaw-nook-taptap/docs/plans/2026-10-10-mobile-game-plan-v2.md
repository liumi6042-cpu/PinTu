# 一起拼图 · TapTap 手机版策划案 V2

日期：2026-10-10  
状态：讨论稿；本次仅修订策划文档，没有修改、部署游戏代码或开通收费。  
范围：TapTap 手机版独立产品。V2 替代 V1 中“与 PC 共享房间”和“每级最多300经验”的建议。  
已确认：普通玩家基础体力50，会员基础体力1000，升级均每级增加1；会员不限累计建房次数，同时最多3个未结束的自建房间。

## 1. 本轮确定的方向

- PC 网页与 TapTap 分开运营，房间、聊天、玩家成长、会员和奖励数据不互通。
- 保留可复用的拼图引擎与图片资产，重做手机前端；PC 的页面、片数和玩法保持原样。
- 游戏启动即大厅。四个页面建议仍为大厅、创建图库、游戏、我的；“我的”是上版建议的第四页。
- 大厅竖屏两列，横屏按空间调整列数，滚动分页加载；提供快速加入、创建房间、筛选。
- 图库提供全部、竖图、横图、方图筛选，片数48/108/300/500，默认108。
- 会员不限累计建房次数，指定图片与私人房间免建房广告；同时最多3个未结束的自建房间。
- 增加长期等级、体力、每十次的小奖励和完图贡献奖励。
- 去掉旧版的拼图记录、宣传说明、QQ群、收藏和语言切换大块区域。帮助、隐私、反馈等集中在“我的”，不占主玩法空间。
- 早前的跨端合作需求已由本轮“两端独立”替代。当前线上版本仍不能声称已经完成后端隔离。

## 2. 手机页面和工具布局

### 2.1 大厅

顶部为紧凑状态栏：头像/等级、体力、小礼盒进度。点击头像进入“我的”。主要按钮为快速加入、创建房间；每日拼图保留一个小按钮，直接按108片进入。

竖屏两列卡片，横屏根据可用宽度调整为3～4列，窄横屏不强求四列。卡片只保留图片、简名、片数、人数、完成进度；优先使用统一预览容器保持排布稳定，进入房间后使用完整原图。默认每次追加12间。实时更新人数、进度时不打乱正在看的卡片和滚动位置。

筛选折叠在一条工具栏内：图片方向、片数、有人在玩、可加入。快速加入尊重筛选，选择未满且仍有足够拼图空间的房间。没有合适房间时提供随机开桌，不自动播放广告。

### 2.2 创建图库

布局从上到下：

1. 返回＋简短标题。
2. 片数：48 / 108 / 300 / 500，默认108。
3. 图片方向：全部 / 竖图 / 横图 / 方图。搜索和分类收进筛选。
4. 两列图片网格，滚动加载。
5. 选中图片后出现固定操作栏，显示公开/私人和创建按钮；图片列表为操作栏留出空间。

图片方向按原图宽高判定，方图使用单独类型。竖图筛选的是图片素材方向，不是锁定手机屏幕方向；旋转手机仍能自适应。保留最近一次筛选偏好，横竖屏切换不重置选择。

“随机图片免费创建”作为明确的独立按钮，仅创建公开房间；随机可以服从片数和方向筛选，但不允许同时指定具体图片。不开放反复刷新预览后免费选定某一张的流程。

指定图片或私人房间：普通玩家看一次完整激励视频创建一次；两者同时选择也只需一次。会员直接创建。先校验房间名额、图片、房型和片数，再播放广告；完成广告后网络失败应保留本次创建权益重试，不能让用户重复看。创建页展示“自建房间1/3”，满额时进入房间管理。

暂不恢复旧版上传图片、自定义房名和大段说明。按图片比例适配网格时，显示实际片数，不把“档位”误当成所有图片均能严格生成相同格数；48片需同步补齐服务端创建和恢复支持。

竖屏布局示意：

    返回  房间简名／人数        等级
    体力条                       礼盒 7/10
    ─────────────────────────
              拼图画布
    ─────────────────────────
    边缘   提示   底图   适配   更多
    系统手势安全区

横屏：状态条变薄，五个主要工具移到侧边，画布使用剩余区域。侧边空间不足时保持单列短按钮，不把工具压到拼块上。

- 每个按钮用图标＋两个字，触控目标建议至少44 CSS像素。固定工具顺序，奖励动画不挤动按钮。
- 双指缩放、拖动画布作为主要视野操作；“适配”一键回到可见全图，“更多”保留明确的放大/缩小操作供不方便双指的玩家使用。
- 提示、底图直接可见；边缘为可切换状态。工具使用次数与广告需求在触发前明确，不突然跳出广告。
- 更多包含聊天、成员、声音/震动和退出。聊天展开时为面板腾出布局空间或暂停画布交互，关闭后恢复；不常驻遮盖拼块。
- 其他玩家操作提示显示“昵称 · Lv.数字”，空闲后淡出。昵称截断，成员列表显示完整名字。
- 指示器颜色用于区分玩家；等级徽章单独着色，避免同等级玩家难以辨认。
- 横竖屏切换保持房间、体力和拼图状态；重新计算画布尺寸、缩放范围和触点坐标。
- 无体力时可查看、缩放、聊天，不能产生新的拼合操作；最后一次操作先完整结算升级和奖励，再决定是否需要补体力。

### 2.4 我的

集中展示等级/经验、徽章、体力上限、会员有效期和权益、账号、声音/震动、帮助、隐私及反馈。通过头像进入，不增加常驻底部导航，不恢复拼图历史页。

会员购买入口仅在平台发行路径及支付权限明确可用后上线。此前可用测试权益验证功能，不把测试状态伪装成正式会员销售。

## 3. 有效贡献、经验和体力

延续 V1 的计数建议：一次真正增加拼图进度的成功操作，消耗1点体力、获得1点经验、增加1次个人贡献。整组成功拼合也按本次1次操作计，不重复归属整组此前的贡献。拖动失败、看图、缩放、重连、重复提交和搬动已完成组不计。

这是按有效操作计数，并非承诺每张108片图恰好产生108经验。服务器必须检查首次产生的连接/归位进度，单凭客户端声称“成功吸附”不能加经验。最终实现前需用现有组块机制验证一次归位、连接和重复吸附不会重复计分。

- 初始Lv.0；首次有效拼合后升Lv.1，升Lv.2还需5次。
- 每升一级体力上限增加1，回满到新的上限。
- 一次完整回体广告只补足当前上限，不提高永久上限。
- 每累计10次有效贡献，自动获得1～5体力，各20%概率；进度跨房间保留。
- 升级不提高单次经验，也不增加完图贡献权重。会员与普通玩家按同样贡献计算经验和奖励。

### 已确认的体力上限

| 玩家类型 | 基础上限 | 等级加成 | 示例 |
|---|---:|---:|---|
| 普通玩家 | 50 | 每级＋1 | Lv.20为70 |
| 有效会员 | 1000 | 每级＋1 | Lv.20为1020 |

用户已明确1000只适用于会员。普通玩家沿用此前基础50；每次升级仍回满当前身份对应的上限。会员经验与贡献奖励没有额外倍率，较高体力容量提供连续游玩的便利。

只算十次奖励、忽略其他收入时，平均净消耗约0.7/有效操作：基础50对应约71次，基础1000对应约1429次的均值估算。升级回满和完图奖励还会延长。此估算不是玩家必定能玩的次数，更不是广告收益预测。

会员体力广告需求会明显更低，这属于会员权益的实际成本，定价测试应计入。普通玩家前期升级频繁也不会很快耗尽体力，不能把50基础体力等同于“拼50次就必须看广告”。

建议首次开通会员时补足会员上限一次，同一订单重复通知不重复补给；提前续购只延长有效期，不靠重复购买回调刷体力。会员到期降低可恢复的上限，已有体力余额自然消耗，不突然没收；等级经验保留。

自然恢复仍是可选项，尚未定案。V1的每3分钟恢复1点，从零恢复普通基础50约需2.5小时，会员基础1000约需50小时；需结合会员升级回满、完图补给和真实使用量再决定是否采用、是否分档，不在此稿默认为已确认。

## 5. 完图体力奖励：按贡献分享

建议将用户提出的“1～100体力”解释为：有真实贡献的玩家，完图后每人至少1点、最多100点；用随片数增加的整局基础奖励池来分配。

| 拼图档位 | 整局基础奖励池 |
|---|---:|
| 48片 | 10体力 |
| 108片 | 25体力 |
| 300片 | 60体力 |
| 500片 | 100体力 |

同样贡献比例、参与人数下，大图获得更多。独自完成可获得全部基础池；多人按个人有效贡献比例分，不把100发给每个围观者。

分配建议：

1. 仅有至少一次有效贡献的真实玩家有资格，贡献为零奖励为零。
2. 记累计有贡献玩家数为K、基础池为B，实际池P取B与K中的较大值。先给每人1，再将P−K按贡献比例分配，余数按最大余数法补齐。
3. 这样普通情况下总额等于基础池；若整局轮换参与者很多，超过基础池人数，则总额扩为每人最低1所需的额度。最大同时在线人数不等于整局参与人数，不能误把两者都固定为8。最低1与严格固定总预算不能同时保证，因此本案明确允许上述保底扩池；需要防止轮换小号刷参与人数，不按未经验证的临时客户端ID重复发奖。
4. 单人奖励仍不超过100。以500片、三人贡献60%/30%/10%为例，按该分法为59/30/11，总计100，保留最低参与奖励。
5. 中途离开的贡献者同样可到账；不以结算时是否在线决定资格。机器人和系统补位不领取玩家奖励，也不能用机器人代拼制造经验。
6. 每个房间的每次拼图实例只结算一次；续局生成新的实例。仅用房间ID不足以区分同房续局。记录实例ID＋玩家ID以及唯一结算事件，防重复发放。
7. 由权威服务记录贡献。最后一块操作者只获得自己的本次贡献，不拿走别人已拼组块的贡献。
8. 免费随机房间可以正常领奖；反复新建、重复请求、空房和未完成房间不发完图奖。新手等级、十次奖励不因换房重置。

### 奖励到账与上限

建议所有玩法奖励自动到账，允许奖励造成少量临时超上限；例如50/50收到5显示55/50，不增加永久上限。广告与升级只负责“补足”，不能把已有超额余额清掉。自然恢复若启用，在达到上限时停止。

同一次操作顺序：验证并消费体力 → 加经验/贡献 → 升级并补足 → 发十次奖励 → 若完图再发个人完图奖励。整个结果一致保存，前端合并展示。玩家看见“+体力”必须实际到账；不要先展示奖励再被升级覆盖。

礼盒进度常驻预留状态栏，自动播放约0.6秒小动画。升级提示短暂显示，不暂停操作。完图用一张简洁结算面板显示个人贡献、经验和体力到账，可选随机下一局或回大厅，不增加长期记录页。

以上是建议数值。贡献按有效操作而非物理片数统计，较大组拼合、多组连锁和机器人补位会影响单位体力与整局奖励的关系，需要用真实开局数据检验；不能仅凭“500片扣500体力”做收益预算。

## 6. 会员权益和价格建议

### 权益

| 项目 | 普通玩家 | 会员 |
|---|---|---|
| 快速加入公开房间 | 免费 | 免费 |
| 随机图片创建公开房间 | 免费 | 免费 |
| 指定图片创建 | 每次完整广告 | 无次数配额，直接创建 |
| 私人房间创建 | 每次完整广告 | 无次数配额，直接创建 |
| 指定图片＋私人房 | 一次广告即可 | 直接创建 |
| 基础体力上限 | 50＋等级 | 1000＋等级 |
| 同时存在的自建房间 | 默认保护上限建议同为3间 | 已确认最多3间 |
| 经验和完图贡献倍率 | 1倍 | 同样1倍 |
| 会员标识 | 无 | 小徽章，可隐藏 |

“不限建房次数”与“同时最多3间”并不冲突：会员不设每日、每月或累计创建次数配额，但其创建且尚未结束的房间最多3个。随机/指定、公开/私人都占用名额；加入别人房间不占自己的建房名额。完成一局并结束该房间或安全关闭空房后释放名额，随后可继续创建。

创建页显示当前占用数，达到3间时先展示现有房间，不能先播广告再报满额。多人正在玩的房间不能为了腾名额直接删除或踢人；长期无人房按明确的回收规则释放名额。同房续局保留原房间名额，但仍需检查新一局的选图与广告权益。还应保留短时防刷和幂等创建，防止连续点击超过3间。普通玩家的并行保护上限建议同样为3间，会员卖点是免建房广告和体力容量。

会员到期只改变之后的创建权益，不立即踢出已进入的房间或删除拼图；等级经验永久保留。到期后体力可恢复上限回到50＋等级，已有余额自然消耗，不突然没收。续购时间从当前到期时间与购买时间中的较晚者顺延30天。

提示/底图是否免广告尚未定案。不要先把“免所有广告”写进会员商品，而实际仍需看体力广告。V1建议每局各2次免费工具使用，之后广告解锁，这是对早前“每次都看广告”的候选调整，正式实现前还需确定。

### 建议售价

首发只做一个商品：**拼友会员，12元／30天，手动续购。**

这是产品测试价，不是TapTap规定价格，也不是已经配置或承诺盈利的售价。现在明确的核心权益是1000基础体力容量、指定图片及私人房免建房广告、不限累计创建次数而同时最多3间。正式商品介绍必须同时说明这些权益及并行上限，不写成无限体力、无限同时开房或免除所有广告。

后续留存和成本稳定时再考虑30元／90天；首版不卖永久会员，不把未经核实的自动续费能力写成已支持。定价复核看：付费转化、会员创建次数、实际房间带宽与计算成本、客服维护成本、替代掉的广告收入，以及实际支付费用和退款。不能直接把售价当净收入。

### TapTap负责什么，我们负责什么

## 7. 后端架构：代码复用，运行和数据独立

多人同步仍然必须存在，但只在TapTap自己的玩家之间进行。建议复制并复用成熟的拼图与房间模块，在TapTap独立服务运行；无需为了分开运营从零重写拼块算法和同步协议。

    PC网站 ────── PC原服务 ────── PC房间／聊天／原数据

    TapTap H5 ── TapTap独立服务 ── TapTap房间／聊天
                         └────── 等级／体力／广告权益／会员

两条业务链路不互相转发房间请求。可以继续放在同一台物理服务器，使用独立进程、端口、数据库或独立数据目录、会话密钥与缓存空间；不是必须立刻购买第二台服务器。是否要拆机器取决于实际容量和稳定性需求。

- 现阶段保留已有HTTP增量同步；当前实现不能称为已经使用WebSocket。先解决手机操作与弱网，再根据测量考虑更换传输方式。
- 复用图片和静态目录时保留授权资料与素材ID，不复制PC真实账号库、房间、聊天、运行数据库或密钥。
- TapTap使用自己的玩家身份和成长数据；已有PC会员、拼图记录不自动导入或通用。
- 当前H5仍通过上游访问原站房间。独立服务完成前不能把“前端独立”表述为“房间已独立”。迁移后旧测试房间链接与正式新房间链接需明确区分。
- 手机创建、片数、私人权限和会员规则在TapTap服务修改，原站继续使用自己的规则。尤其移除对PC上游的创建、聊天、鼠标和同步请求。
- 同步、扣体力、加经验、奖励、完图结算在权威服务一次性协调；重复请求不会重复计费，断线不丢账，跨设备不能绕过体力。
- TapTap后台中的多人联机服务不是完成隔离的前提，可继续使用自有独立后端。
- 聊天分开并不自动完成内容管理。TapTap首版建议先用预设合作短语与表情；若保留自由文本，应单独具备频率限制、举报、屏蔽及处理入口，不把PC聊天通道直接接过来。这是降低管理负担的产品建议。
- 平台协议对同一内容的不同版本服务质量有要求；隔离房间本身不能被当作规避平台规则的方式。商业化上线前应一并核实PC与TapTap差异是否符合所选发行方式，避免在平台内引导玩家转去外部付费。[平台协议第4.5、4.8条](https://developer.taptap.cn/minigameapidoc/tap-operation/platform/development-agreement/)

## 8. 开发顺序与验收

1. 完成四页低保真布局和横竖屏工具区域，按普通50／会员1000和会员同时3间设计；工具广告和聊天方式仍待定。
2. 在TapTap副本建立独立房间服务及数据空间，切断对PC房间上游的依赖。用PC和TapTap各建房验证双方房间列表、聊天、身份与记录互不串入。
3. 实现手机界面、图库方向筛选、48～500档位和触控布局；验证48片开局及恢复。
4. 增加权威成长与奖励结算；验证新手1/5经验、长线等级、体力为0、十次奖励、完图奖励、离房到账、多人轮换、重复回调和同房续局。
5. 验证免费随机创建、指定及私人房一次广告、会员不限累计建房但同时最多3间、并发请求不能超限、失败后保留创建权益及成员加入不重复付费。
6. 真实设备验证竖屏两列、横屏自适应、图片方向、工具触控区域、胶囊安全区、横竖切换、切后台恢复、多人争抢和弱网。
7. 支付路径可用后再做沙箱支付、商品审批、会员有效期、补单和退款；在具备条件前不展示可购买的正式商品。

重点数据：每人每天有效贡献、各等级耗时、体力净流入/流出、首次耗尽时点、广告请求可用率、创建成功率、会员建房成本与完图奖励发放。会员1000体力和升级回满可能让会员体力广告很少，这应通过测试验证，不以预计广告频次倒推修改已售权益。
