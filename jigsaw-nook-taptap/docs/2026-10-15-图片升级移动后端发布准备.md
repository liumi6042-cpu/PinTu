## 服务器准备命令

先将稀疏包以及以下两份脚本传到同一服务器 `/tmp`。脚本只含操作代码，不包含 SSH 凭据。

- `scripts/rebuild-mobile-full-from-sparse.py`，SHA256 `87aa7a9b4def842baed3e9c95b480c92ff824526c1b011ddab811e47bf01c1f4`。
- `scripts/upgrade-mobile-backend.py`，SHA256 `74e3bbd79c5de1d2f1ab9e30b3206cd2033ab31e0bece2993742cda65882ccff`。

只在 `/tmp` 重建完整包，不改 current，不重启服务：

```sh
python3 /tmp/rebuild-mobile-full-from-sparse.py \
  --archive /tmp/jigsaw-mobile-sparse-20261015-artwork40.tar.gz \
  --sha256 84c31e721673a1f19035a38ee561ee548fb50cab329cbc9c70b393195ead8f54 \
  --expect-current 20261015-freealbums39 \
  --output /tmp/jigsaw-mobile-backend-20261015-artwork40-rebuilt.tar.gz \
  --validator /tmp/upgrade-mobile-backend.py
```

重建工具先验证当前版本和 manifest，再验证复用文件、稀疏文件、完整 889 文件，最后调用原升级验证器再验完整 tar。重建的 tar 元数据与 Windows 原包不同，因此其 SHA256 以重建工具实际返回值为准，不能套用本地完整包的 SHA256；内部完整 manifest 必须仍为上面的 `2f90ac…`。

在本会话协调的上线窗口先预检。`--sha256` 使用重建结果，`--pc-service` 使用当时实际运行的 Web 端口；准备时是 3103，若 Web 先切换至 3104 则相应调整。

```sh
python3 /tmp/upgrade-mobile-backend.py \
  --release 20261015-artwork40 \
  --expect-current 20261015-freealbums39 \
  --archive /tmp/jigsaw-mobile-backend-20261015-artwork40-rebuilt.tar.gz \
  --sha256 <重建工具返回的SHA256> \
  --pc-service jigsaw-web@3103.service \
  --check-only
```

预检通过后，使用同一组参数去掉 `--check-only` 才会备份数据库并切换移动后端。升级脚本还会在切换前执行包内严格画质校验，校验 34 张／68 文件。切换失败会退回旧代码，保留当前共享数据库，不恢复旧数据库快照。Web、旧 H5、环境文件及其服务状态受到独立校验保护。

保留 39 版及其指向的 38 版公开资源目录用于回退，本次不做旧版本清理。
