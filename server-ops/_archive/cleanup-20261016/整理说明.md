# 拼图项目整理与清理入口

本次已经完成整个项目的盘点、清理清单审核和后续构建清理修复。**现有大目录尚未删除**：Codex执行原生删除命令时被自动审批以 `blocked by policy` 拒绝，没有提供更具体原因；没有换工具重试。

需要在本地运行时，双击本文件同目录的 **执行清理.cmd**。它只使用清单中的678项已审核路径，不会改动系统权限或执行策略。只看预览可运行 `Invoke-ReviewedCleanup.ps1`，默认没有删除；入口文件明确传入 `-Apply` 才执行。若此后素材登记发生变化，脚本会在删除前停止，要求重新核对。

入口已修正为 ASCII 内容与 Windows CRLF 换行，避免旧入口在切换 UTF-8 时被 CMD 截断、尚未调用 PowerShell 就退出。已从 CMD 实际运行 `--preview --no-pause` 验证678项预览正常；仅为预览，没有执行删除。正常双击会执行审核清单并保留窗口，启动状态记入 `launcher-status.log`，PowerShell输出和错误记入 `launcher-output.log`。

清理范围是旧构建临时目录、测试解包目录、历史发布展开目录、已交付的上传分片、可再生成的dist、已验证重复ZIP及独立QA沙盒。已把137份旧发布清单压缩保存在 `retained-stage-manifests.zip`，方便核对历史。

保留所有源码与Git历史、未提交开发、图片原件及生成证据、当前相册与奖励设置、真实管理/玩家数据库、当前和上一回退的完整发布包、小程序40完整基线和41稀疏包、尚未发布的小程序审核包及现有依赖。原版依赖被正式Web工作树通过目录联接使用，本轮明确排除删除。各项目与工作树路径继续保留，避免已有会话或文件路径失效。

脚本先核对根路径、候选实际路径、父级链接、保护路径和素材登记摘要；删除前拒绝新的目录链接，不跟随链接目标。每项删除会检查是否实际消失，并写入 `cleanup-progress.jsonl`；结束后核对受保护图片摘要和磁盘实际空闲增量。个别锁定项会记录失败，不能把部分成功表述成全部清理完成。

Git占用约7.08GB，包括根仓库和两个独立游戏对象库。Git保留代码版本，不负责自动清理未跟踪的构建副本。本轮补充根目录忽略规则，防止嵌套仓库、临时工作目录、Python缓存和本机盘点记录被误加进源码仓库；没有改写历史、执行reset/clean或删除Git对象。由于当前D盘余量不足，未冒险运行需要额外临时空间的Git重新打包。

持续增长问题也已修复：

- 正式Web的构建、打包和临时源码清理统一改为安全的异步清理，失败也逐项回收并记录残留；完整回收之后才标记发布包验证完成。提交 `209198b`，6项轻量测试通过。
- 小程序的测试解包和H5/server固定中间目录采用有边界检查的清理，等待测试进程退出后删除；显式 `KEEP_STAGE=1` 才保留测试解包。3项轻量测试和脚本语法检查通过。保留原有未提交开发。
- 在本机Node v24.13.0的中文路径小夹具中复现：同步 `fs.rmSync` 返回成功却未删除目录；异步 `fs.rm` 能实际删除，新增回读检查能发现残留。官方也有相应的[非ASCII路径问题记录](https://github.com/nodejs/node/issues/56049)。这与Codex工具的自动审批拒绝是两个不同问题；没有更改全局Node安装。

本轮没有更新服务器，也没有更改线上相册或玩家数据。清理执行后，回到Codex告知“已运行清理”，即可按结果文件继续核对。
