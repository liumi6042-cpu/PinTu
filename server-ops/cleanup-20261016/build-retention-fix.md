# 游戏构建临时目录限留修复

2026-10-16。本次仅修改 `jigsaw-nook-taptap` 的构建与测试生命周期；未构建、未部署，未删除原有历史目录，未改后台配置或玩家数据库，未提交已有开发改动。

## 已实施

- `tests/mobile-package-smoke.mjs`：解包后的全部阶段进入同一个 `try/finally`；实际子进程退出后清理本轮 `work/mobile-package-check/run-*`。即使解包/校验失败也清理。仅显式环境变量 `KEEP_STAGE=1` 才保留完整调试目录。
- `scripts/build-h5.mjs`：开始使用 shell staging、H5 输出、ZIP staging 时先清掉旧产物，避免过期哈希文件继续累积。
- `scripts/package-h5-server.mjs`：准备固定 server staging 前清掉旧产物；其他版本的完整包、稀疏包与清单不受影响。
- `scripts/generated-stage.mjs`：仅允许上述四个精确生成路径及临时测试 `run-*`；拒绝源码/数据/父级路径、目录联接、符号链接和内部链接，清理后回读确认，不能静默宣称成功。

## 已找到的本机问题

本机 Node v24.13.0 的 `fs.rmSync` 在项目中文路径下返回后文件依然存在，已用仅几字节的隔离夹具复现。这与 Node 官方 [非 ASCII 路径删除缺陷 #56049](https://github.com/nodejs/node/issues/56049) 一致；历史脚本有 `finally` 也不代表临时目录实际删掉。

本修复使用标准异步 `fs.rm` 并核对删除结果；相同中文路径的夹具验证通过。未修改全局 Node 安装，也未用其他工具绕过任何审批拒绝。其他仍使用原生 `rmSync` 的历史构建脚本，应在后续实际使用前改用同等安全清理或已修复的 Node 版本。

## 验证与保留

3 项聚焦测试通过：旧文件清理与路径边界、实际退出/已退出/失败准备的生命周期、显式保留与链接父目录拒绝。4 个修改脚本语法检查通过；未运行大型构建或完整游戏回归。

候选清单 `candidates-games.json` 为527个已展开路径，逻辑尺寸44,995,307,256字节；与保留列表没有父子覆盖。实际释放量由主清理按硬链接去重统计，不能把逻辑尺寸当作必然释放空间。mini40完整基线、41稀疏包/清单、当前审核客户端、真实数据和未提交源码均保留。
