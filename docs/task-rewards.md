# 任务奖励管理

管理网站的“任务奖励”独立保存奖励设置，不需要建立图片草稿或发布图片版本。保存成功后，已接入配置文件的游戏服务在下一次操作时读取新数值，无需重启服务。

可调整五个协作/好友任务的体力和经验、分享邀请的体力与经验及每日次数、好友加入补满包的经验、十格小礼的最低体力、三个等级档的最高体力与经验。默认值与原来的任务系统一致。任务完成条件、十次有效拼合的计数、邀请资格与好友加入每日最多三份均保持原规则；好友加入礼包仍然补满体力。

每份礼包发放时保存其实际体力、经验与奖励范围。修改设置只影响之后的新奖励，已存礼包按原值开启；混合库存显示合并范围。补满包保留满体力时不能消耗的规则，先应用礼包保存的经验，再补到当前体力上限。领取请求和每日任务标识继续使用原有稳定标识，重复请求不会再发一次。

共享玩家端会显示服务返回的当前奖励。完整邀请链接复制成功或浏览器系统分享确认完成后申请分享奖励；仅打开微信分享面板、取消或失败不会申请。奖励响应中断时保存原请求，点击分享后重试同笔领取。微信目前的分享接口只提供“已打开面板”的状态，因此不会将打开面板计作成功分享。

服务设置 `MOBILE_TASK_REWARDS_CONFIG` 为公开配置文件路径。本地 `scripts/start-mobile.mjs` 自动发现 `../content-admin/work/task-rewards/configuration.json`。未设置此变量时使用 `config/task-reward-defaults.json` 的原默认值。线上代码包包含读取模块与默认配置；管理网站保存的公开配置还需要同步到游戏服务器对应路径。

公开格式为 `jigsaw-task-rewards/v1`，字段为 `tasks`、`invitationShare`、`invitationFriend`、`tenGrid`。管理网站保存纯设置，桥接文件添加规范化内容的 SHA-256 校验值。服务每个请求使用一次完整设置，并按文件变化重新验证；配置损坏或不可读时拒绝本次操作，避免错误发奖。配置文件不包含玩家记录或凭证。

聚焦验证覆盖原默认值、热更新、分享重试、同日不可重复发任务礼包、新旧库存、十格小礼随机范围和补满包经验。
