# 每日拼图出场与图鉴收录方案

日期：2026-10-12。本文为流程设计，尚未实现排期、出场记录或自动收录。现有后台内容与游戏运行规则保持当前状态。

## 推荐的日常操作

每日拼图使用同一张图片、同一个图片 ID。相册是归属，每日拼图是一次按日期安排的展示，两者不需要维护两份图片。

1. 上传图片、设置画风和题材标签。
2. 提前选择归属相册，例如「二次元 · 异想人物」。
3. 为图片安排每日首发日期。首发前，在后台所属相册中可见，玩家普通图库与图鉴暂不公开这张图片。
4. 首发当天，通过每日拼图入口展示。符合完成规则的玩家当时就保存这张图的完成记录。
5. 首发结束后的北京时间次日 00:00，在预选相册的普通图库与图鉴中公开，不需要再搬图。

相册的 PC / 小程序显示选项继续生效；隐藏相册不会因每日出场自动变成公开相册。购买设置与已有购买权益保持。每日免费体验所取得的完成记录，在图片归入购买相册后也不能被清除。

## 后台怎样看出已经出现

图片卡片与详情显示每日状态、首次出场日期、后续重复出场次数和归属相册。每日日期直接在图片详情安排，不增加另一份草稿或独立的日常整理流程。

| 状态 | 展示信息 | 运营操作 |
| --- | --- | --- |
| 已排期 | 首发日期、归属相册 | 可调整尚未生效的排期 |
| 今日每日 | 今日日期、归属相册 | 查看当天展示 |
| 已收录 | 首次出场日期、收录日期、归属相册 | 无需再移动图片 |
| 已出场 · 待归相册 | 已确认的出场日期，缺少归属 | 选择相册，处理历史或异常遗漏 |
| 待同步 | 已保存排期，但游戏端尚未确认生效 | 完成发布接入 |

素材库增加「每日状态」筛选，其中「已出场 · 待归相册」用于集中发现遗漏。「每日专用」不再作为新图的最终存放相册；新图提前归入真实画风相册。

## 出场记录必须可信

后台保存计划不等于游戏实际展示，不能仅因为后台日期过期就标记「已出场」。计划需要由已发布游戏读取；记录实际生效的日期、图片 ID 与应用，保存不可被后续排期修改覆盖的历史。

每日采用固定的日期 → 图片 ID 记录。已生效日期锁定，调整未来安排不能改变过去哪天出现了哪张图。重复推荐同一张图片增加出场次数，保持首次出场日期与图鉴归属。

## 当前代码核查

目前静态素材中有 3 张每日专用图片。`jigsaw-nook-taptap/lib/daily-puzzle.ts` 按北京时间天数对每日素材池长度取模轮换，没有运营排期、独立出场历史或首次出场日期。当前算法能推算本版目录会选择什么，不能证明历史部署实际出现过什么。

`server/mobile-service.mjs` 创建每日房间时记录每日日期与图片，但该记录只覆盖有玩家创建房间的日子，不能代替完整的运营出场历史。

图鉴目前只接收普通图库素材。每日专用图片不在这份素材列表里，所以每日完成收据的图鉴资格为未收录。单纯在后台移动相册或者以后把图片放进图库，都不会自动补好已有玩家的每日完成记录。

Web 与小游戏仍未读取后台共用相册，自动收录需要随共用相册配置接入一起实现，不能仅在后台加一个显示标签就声称玩家端已生效。

## 实现与历史兼容要点

- 将每日排期与实际出场档案分离；以北京时间为统一日期边界，保持一天一张和两端共用图片 ID。
- 普通图库可见范围、图鉴公开范围与可保存完成记录的范围分开处理。每日图暂未公开时也应允许合格参与者保存完成事实，公开后沿用同一份完成标记。
- 对现有 3 张每日图先标记历史待确认；没有可靠证据的首次出场日期保持未知，不按循环算法杜撰过去日期。
- 对留存的旧每日房间与有效参与完成事实单独设计进度补录。仅补图鉴完成标记，不重新发放金币、碎片或其他已结算奖励。旧完成收据不能简单重放。
- 保留已有图片 ID、玩家完成记录、购买与奖励的兼容关系；配置更新不改历史日期的选图结果。

本次只读检查了源码，没有读取真实玩家数据库或修改游戏内容。图片整理的最新状态见 [相册整理记录](2026-10-12-图片相册整理.md)。
