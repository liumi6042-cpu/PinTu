# 每日拼图出场与图鉴收录方案

日期：2026-10-12。用户最终选择「出现后自动进入预选相册」。后台首发设置、可信出场记录、次日自动收录和小游戏运行适配已实现；正式游戏尚未启用这次接入，现有 Web 不会因后台保存自动上线。

## 推荐的日常操作

每日拼图使用同一张图片、同一个图片 ID。相册是归属，每日拼图是一次按日期安排的展示，两者不需要维护两份图片。

1. 上传图片、设置画风和题材标签。
2. 在图片详情展开「每日首发」，勾选自动收录，预选收录相册，例如「二次元 · 异想人物」。设置预选相册时不提前搬图。
3. 新安排默认勾选「自动安排日期」，无需手选日期。系统从北京时间明天起安排到首个空闲日期，每天一张，跳过已有安排；取消自动勾选后也能手动指定日期。应用修改后点击顶部「保存」，查看确认后的具体日期。尚未接入或恢复的素材可以先保存安排，但不会被导出为实际可用排期。
4. 首发当天，通过每日拼图入口展示。符合完成规则的玩家当时就保存这张图的完成记录。
5. 首发结束后的北京时间次日 00:00，在预选相册的普通图库与图鉴中公开，不需要再搬图。

相册的 PC / 小程序显示选项继续生效；隐藏相册不会因每日出场自动变成公开相册。购买设置与已有购买权益保持。每日免费体验所取得的完成记录，在图片归入购买相册后也不能被清除。

## 后台怎样看出已经出现

图片卡片与详情显示每日状态、首次出场日期、后续重复出场次数和归属相册。每日日期直接在图片详情安排，不增加另一份草稿或独立的日常整理流程。

| 状态 | 展示信息 | 运营操作 |
| --- | --- | --- |
| 已排期 | 首发日期、归属相册 | 可调整尚未生效的排期 |
| 今日每日 | 今日日期、归属相册 | 查看当天展示 |
| 已收录 | 首次出场日期、归属相册 | 无需再移动图片 |
| 已出场 · 待收录 | 已确认的出场日期 | 次日自动收录；后台定期同步 |
| 待游戏确认 | 首发日期已到，但游戏尚无可信出场记录 | 确认游戏启用安排，避免提前收录 |
| 每日轮换 | 原每日图库中的轮换图，缺少可信历史首发日期 | 可继续轮换，也可另行安排首发与收录 |

素材库的「更多筛选」增加「每日状态」，可集中查看每日图片、已排期、今日每日和已收录图片。「每日专用」不再需要作为新图的最终存放相册。现有每日素材的历史日期保持未知，没有为真实图片随意安排日期。

未安排首发的日期沿用原每日图库轮换，目前是三张已登记每日图片，按固定顺序循环，不是从整个图库随机挑选。普通图片没有勾选首发，不会自动进入新首发队列；原每日轮换图片继续参与默认轮换，和相册摆放无关。

自动安排的日期保存后保持固定，刷新、重复保存、过期但尚未确认出场，都不会悄悄重新排期。取消尚未生效的安排可以释放日期，但不会重排其他已保存计划。旧手动日期与真实出场事实保持。

## 出场记录必须可信

后台保存计划不等于游戏实际展示，不能仅因为后台日期过期就标记「已出场」。计划需要由已发布游戏读取；记录实际生效的日期、图片 ID 与应用，保存不可被后续排期修改覆盖的历史。

每日采用固定的日期 → 图片 ID 记录。已生效日期锁定，调整未来安排不能改变过去哪天出现了哪张图。重复推荐同一张图片增加出场次数，保持首次出场日期与图鉴归属。

## 修改前代码核查

目前静态素材中有 3 张每日专用图片。`jigsaw-nook-taptap/lib/daily-puzzle.ts` 按北京时间天数对每日素材池长度取模轮换，没有运营排期、独立出场历史或首次出场日期。当前算法能推算本版目录会选择什么，不能证明历史部署实际出现过什么。

`server/mobile-service.mjs` 创建每日房间时记录每日日期与图片，但该记录只覆盖有玩家创建房间的日子，不能代替完整的运营出场历史。

图鉴目前只接收普通图库素材。每日专用图片不在这份素材列表里，所以每日完成收据的图鉴资格为未收录。单纯在后台移动相册或者以后把图片放进图库，都不会自动补好已有玩家的每日完成记录。

Web 与小游戏仍未读取后台共用相册，自动收录需要随共用相册配置接入一起实现，不能仅在后台加一个显示标签就声称玩家端已生效。

## 已实现的接入与兼容

- `dailyPlans` 与草稿一起保存，一天一张、每图一份首发安排；旧 v3 内容默认空计划。快照和来源合并保留安排。
- 自动计划使用可选 `autoDate: true`，在后台保存时确定具体日期；公开运行配置仍只包含日期、图片和相册，不改变小游戏接入格式。旧计划缺少这个字段时继续作为手动日期。
- 出场档案与收录事实保存在后台私有独立表中；游戏只交换公开配置和不含玩家身份的出场记录，不访问管理员数据库。
- 正式游戏启动后只确认真实当前日期。已生效日期、图片和预选相册锁定，未来配置修改不能改变过去的出场事实。
- 首发当天，合格参与者就可保存图鉴完成事实；次日公开到预选相册，并沿用同一个图片 ID 的完成标记与难度记录。
- 自动收录通过同一当前工作内容的事务与修订号校验完成，保留元数据、标签、价格与奖励，只移动该张图片并修复封面。独立收录事实防止重复搬图。
- 后台每 30 秒同步事实，干净页面自动载入变化；有未保存编辑的页面保留本地内容并提示合并，不强行刷新。
- 原 PC 项目未替换。小游戏默认保留静态轮换，显式启用公开排期文件后才使用新规则。本次只适配每日图片，不顺带部署全部相册或 53 张待接入新图。
- 原购买包成员、价格、权益与奖励收据保留。新免费相册可收录每日图片；旧购买包可增加每日图片。新建购买相册的商店接入仍需完成，未就绪时排期保留为待接入。
- 旧每日房间的图鉴完成补录仍需另行依据有效历史证据处理，不能重放已结算奖励。

后台生成的公开配置位于 `work/daily-bridge/configuration.json`。小游戏通过 `MOBILE_DAILY_CONFIG` 显式读取；实际出场目录 `MOBILE_DAILY_APPEARANCES` 默认是小游戏 `work/daily-appearances`。后台读取该目录并核对配置摘要后收录。运行说明见 [小游戏每日接入](../../jigsaw-nook-taptap/docs/daily-content.md)。
