# Web 托管内容与成长奖励

本次仅在 `puzzle-play` 接入后端，尚未部署线上。共享配置遵循管理端的四文件发布协议；每个操作固定持有一份已验证版本，Web 跳过全部体力产出、消耗、恢复和界面字段。

## 玩家资产与兼容性

新增 `0015_managed_content_economy.sql`，资产按实际账号或持久游客身份保存，使用独立玩家表、版本号 CAS 和稳定奖励收据。未读取或修改旧庭院的碎片、花园、孵蛋、气泡和指针库存。金币和碎片不得扣为负数；并发领取、重复购买和重复合成只执行一次。

升级公式和数值与小程序一致，初始等级 0。有效拼合从服务器提交后的 `room.achievements.contributors[owner].count` 读取，拖动、错误尝试和单纯进房不算。启用时记录旧房间贡献基线，不追补之前完成的房间。

相册收集采用当前成员；每册自己的稳定里程碑只奖励一次，保留已发数值和装饰快照。购买时保存永久图片权益；图片移动或移出可见相册后，接口仍返回 `retainedImages` 供“已购珍藏”入口继续使用。每日图片依共用每日算法选择，当天可以免费开房。

## 任务与邀请

共桌任务为每日 10、30、60 次有效拼合，好友任务为每日 10、30 次。另一位真人伙伴需要在线且在此前两分钟内有有效拼合。好友关系必须互相接受请求，或为已绑定的邀请关系；接受好友、绑定邀请码本身不增加拼合进度。

分享接口仅在前端成功复制或分享链接后调用，按配置每日次数和稳定请求编号防重。服务器生成 12 位随机邀请码，不能自己邀请自己，首次绑定不可被另一个邀请覆盖。受邀伙伴累计完成 3 次绑定后的有效拼合才生成邀请礼物，每天最多 3 位，额外数量不顺延。礼物只包含金币与经验，已生成的数值不随后台修改而变化。

## 持久奖励事件与故障恢复

`0016_managed_reward_outbox.sql` 新增奖励事件表。房间 CAS 更新后紧接着执行 `INSERT ... SELECT ... WHERE changes()=1`，两条语句处于同一批事务。失败的房间 CAS 不产生事件。

`prepareManagedRoomEvent` 在提交前记录原事件时间、各玩家贡献、真人合作/好友条件、当时邀请绑定和原发布版本的 Web 奖励快照。收据不保存房间票据或拖动租约。正常或恢复结算都从收据读取，采用原北京时间日期，不能把昨晚的任务计到今天。

已知版本使用原快照。若原配置读取失败，仍记录事实，恢复时固定采用第一个有效发布版本；服务器保存该次选择和来源为空的事实，并向玩家明确说明实际采用的版本。不会宣称找回了原版本。重复恢复保留第一次选择和已发奖励。

玩家接口返回 `settlement`，含待结算数、未知快照数、说明和最近恢复的版本。待结算时禁止领取及资产消费。共享配置不可用时返回 503 和“奖励待结算，暂时不能领取，请稍后重试”，同时只读查询当前身份的待结算情况。

## 接口与集成点

- `GET /api/player-content`：成长钱包、相册、永久珍藏图片、任务、礼物、好友、邀请、装饰及结算状态。
- `POST /api/player-content`：购买相册、合成/装备装饰、领取任务/礼物、成功分享后记奖、接受邀请、请求/接受好友。
- `prepareManagedRoomEvent(room, previous, content, occurredAt, {unavailable})`：生成待插入的事实；未启用托管内容时返回空。
- `drainManagedRewards(content, owner?)`：按原时间顺序处理已提交事件。
- `managedImageAllowed`、`managedAccessibleImageIds`：新建房间的相册权益检查，不改变旧房间加入或继续拼图。
- `ownedManagedCursors`：批量返回已持有并装备的托管指针，旧装扮状态仍独立保存。

## 聚焦验证

`tests/managed-economy.test.mjs` 的 6 项纯模型检查，和 `tests/managed-economy-store.test.mjs` 的 7 项真实异步 SQLite 存储检查通过；类型检查通过。验证包含非零金币/经验、旧基线与首个新拼合、并发领取/购买、永久图片权益、旧庭院原文不变、真人好友与邀请门槛、跨日原快照恢复、未知配置的显式恢复策略、失败 CAS 不记奖和重复恢复不重发。测试只使用独立内存数据库。
