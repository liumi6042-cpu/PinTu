# TapTap 账号与好友能力接入边界

日期：2026-10-17，2026-10-18 更新。当前完成了 TapTap 原生好友面板入口、移动端服务/隐私说明合并，以及本地账号绑定纵向流程；本次仍未上传或部署。

## 当前能做什么

- TapTap 小游戏提供 `tap.openFriendList()`，可打开平台好友面板；TapTap 文档说明该面板包含平台关注/好友、游戏状态和聊天。用户互相关注成为平台好友。
- TapTap 登录 `tap.login()` 提供一次性临时 code。必须把 code 交给游戏服务器，再由服务器用小游戏 AppID/secret 调用 `code2Session`，得到 openid 等身份数据；secret、session_key 和平台凭据不能下发客户端。
- TapTap 昵称不是 `tap.login()` 的返回值。`tap.getUserInfo()` 需要 `scope.userInfo` 授权；未授权时应在 TapTap 要求的用户操作按钮上取得用户选择，不能在静默启动时假装已经授权。
- 现有 TapTap 客户端登录后仍创建独立游客凭证。若直接把 identity 改成 openid，会令现有游客档案、房间凭证和历史数据无法对应；接入必须先做账号映射和不丢档案的绑定/冲突处理。

## 本地实现

TapTap 运行环境提供 `tap.openFriendList()` 时，“好友”面板会显示“TapTap好友”入口。入口由玩家点击后才调用宿主 API，不读取好友名单、不把 TapTap 好友写进游戏服务器的好友表。游戏内好友编号、邀请和屏蔽仍保留为独立功能。

TapTap 账号绑定已接入本地 H5 预览：进入游戏后会在 TapTap 宿主存在 `tap.login()` 时尝试恢复绑定；点击头像的“绑定账号”会再次登录并按用户操作请求昵称授权。服务端只保存经过哈希的 openid/unionid 映射、昵称和当前游客档案映射，不保存 `session_key`，也不把密钥放入前端。绑定后的资源状态包括等级、经验、金币、碎片、已购图包、装饰、任务礼包、库存和房间归属；同一 TapTap 账号与已有非空游客档案冲突时返回保护性错误，不自动合并。

服务端使用官方国内 `auth/v1/jscode2session` 接口。运行时必须显式设置 `TAPTAP_APP_ID` 与 `TAPTAP_APP_SECRET`，不再使用旧的默认 AppID；密钥只放服务器环境变量。未配置密钥、宿主不提供登录能力或用户拒绝授权时，玩家仍可继续以游客身份游玩。

首次说明现在把服务条款和隐私说明合并为一页。进入按钮保留一次明确选择；香港存储及所需个人信息处理不能以默认勾选或静默启动代替同意。版本号已提升至 `2026-10-17.2`，用户会看到更新后的合并说明再选择进入。TapTap好友面板本身仍由 TapTap按其规则发起平台隐私/好友授权。

## 完成账号接入前的配置与验收

1. 在 TapTap 开发者控制台确认小游戏登录与头像昵称能力可用，并核对**小游戏 AppID**（不是数字开发者ID或游戏数字ID）。
2. 由开发者在服务器密钥管理中设置 AppID 与 secret；secret不发到聊天、不写入仓库和构建包。
3. 服务端实现一次性 code 校验、openid 哈希映射、会话签发、重放/频率保护及绑定冲突处理。先用旧游客档案验证同一账号绑定和跨设备恢复，确认旧进度、权益、房间成员记录不会丢失。
4. 昵称读取做为独立可选授权；拒绝后保留游戏生成昵称。不要读取或保存用户资料中与昵称功能无关的字段。
5. 在 TapTap 后台隐私保护指引中如实申报使用的数据类型；通过真实自测二维码检查登录授权、拒绝、过期、换设备、重复code、已有游客数据冲突及好友面板。
