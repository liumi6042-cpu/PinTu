# Web 与小程序共用管理后台

## 用户确认的规则

- 相册、每日图片、任务奖励、成长、金币与装饰统一管理。相册分别设置 PC / 小程序是否显示。
- 任务奖励共用同一份数值。Web 不显示、不消耗、不发放体力；其余金币、经验等奖励与小程序一致。
- 任务奖励新增金币：每项 `tasks[].coins`、`invitationShare.coins`、`invitationFriend.coins`、`tenGrid.coins`，整数 0–100000。旧存档缺失按 0 读取，不因读取改写后台数据库。已生成礼包/已领取记录维持原快照，不追补。
- 保存用于后台编辑和本地预览；“提交到双端”先展示已保存内容，再由管理员确认提交。确认后的同一版本同时供两个后端读取。
- 小程序拼图区增加对齐实际行列的细虚线格子，位于拼块下方，随缩放和平移变化。

## 分工与文件边界

- 管理协调会话：`content-admin`、共享发布协议、发布连接、后台提交界面、Web 界面验收与统一发布窗口。
- 小程序开发：`jigsaw-nook-taptap` 的配置读取、金币奖励结算、任务显示、虚线网格及小程序部署包。
- WEB开发：`puzzle-play` 的相册、任务、装饰与成长系统，桌面界面及 Web 部署包。
- 各项目不覆盖其他项目的工作文件、玩家数据库或后台已保存配置。保留玩家账号、房间、永久购买权益及既有领取记录。

## 固定发布协议

协议来源：`content-admin/contracts/content-release.mjs`。两端将其复制为各自 `server/content-release.mjs`，并纳入部署文件清单。纯 Node 内置依赖，同步读取整份配置。

```js
readManagedRelease(root, { releaseId?, strict? })
// => { pointer, manifest, documents, files, releaseDir, manifestSha256 }
// current.json 缺失时返回 null；strict:true 则拒绝。
```

`JIGSAW_CONTENT_DIR` 指向发布根目录（线上计划 `/srv/sites/jigsaw-content`）。无已发布指针时保留既有配置；存在时整份读取并验证，再选取本次操作需要的配置，禁止跨版本拼接。无效版本应报错，不能默默降级成另一套配置。

```text
current.json
releases/<releaseId>/manifest.json
releases/<releaseId>/albums.json
releases/<releaseId>/daily.json
releases/<releaseId>/game-settings.json
releases/<releaseId>/task-rewards.json
```

- 指针：`{schema:'jigsaw-content-pointer/v1',releaseId,manifestSha256}`。
- 清单：`{schema:'jigsaw-managed-release/v1',releaseId,createdAt,sourceVersions,files:[{path,bytes,sha256}]}`。
- 来源版本：`{draftId,draftRevision,gameRevision,taskRevision}`。
- `documents` 的键是 `albums`、`daily`、`gameSettings`、`taskRewards`；内容维持各自公开桥接配置格式及 `configDigest`。
- 可选 `assets.json`：`{schema:'jigsaw-content-assets/v1',images:[{id,available}],configDigest}`，只用于校验交付状态，不含本机路径。
- 不存在 Web 专属奖励配置。Web 对同一任务配置中的体力字段跳过处理。

## 后端验收接口

两端提供 `scripts/check-content-release.mjs`，从以下环境变量读取待验收版本；只读验证，成功退出 0，失败退出非 0，禁止写玩家数据库：

- `JIGSAW_CONTENT_RELEASE_DIR`：不可变版本的绝对目录。
- `JIGSAW_CONTENT_RELEASE_ID`：版本 ID。
- `JIGSAW_CONTENT_MANIFEST_SHA256`：清单摘要。

现有健康接口增加 `contentReleaseId`，必须实际读取并验证当前指针与配置；未启用时为 `null`。不返回磁盘路径或连接信息。

## 提交流程

1. 管理员先保存相册与各项数值。
2. 后台从已保存内容生成不可变发布快照，展示相册、可用图片和未交付图片数量。
3. 点击确认时再次核对保存版本与内容；预览后有新保存则要求重新预览。
4. 上传公开配置，分别运行 Web / 小程序预检。
5. 两端预检通过后原子切换同一个 `current.json`，无需每次重启服务。
6. 两端健康接口均确认相同版本才显示成功；失败恢复旧指针并验证回退。连接中断等不确定情况不得报告成功。

后台接口：`GET /api/releases/status`、`POST /api/releases/prepare`（空对象）、`POST /api/releases/confirm`（`releaseId`、`manifestSha256`）。沿用管理员登录和防伪令牌；浏览器不可提交服务器路径或执行命令。

私有连接配置位于已忽略的 `content-admin/work/publish-config.json`。密钥、玩家数据库和后台原始数据库均不上传。
