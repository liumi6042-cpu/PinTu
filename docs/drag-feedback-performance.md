# 拖动及轻触反馈改进（2026-09-13）

> **2026-09-17 更新：本文描述的「浮动图层」拖动方案已被回退删除。** 该方案虽然把每帧开销从约 9.8ms 降到 0.023ms，但它把拼块位置从「一份数据」改成了「锚点 + 位移」两处相减，先后引出两个线上故障：拖动时拼块消失（位移恒为 0）、以及定位与维护成本偏高。用户明确要求回到最初的拖动方式，因此 `lib/drag-image.ts`、`.dragged-piece-image` 样式与相关测试均已删除，拖动恢复为每帧从背景缓冲还原新旧脏矩形、再直接重画拼块。**代价是当初被修掉的拖动卡顿会一并回来**，这是用户在知情后选择的取舍。
>
> **本文中与音效、暖光有关的部分仍然有效并保留**（`lib/snap-sound.ts`、`app/sound-control.*`、`content/locales/en.json`、`docs/connection-feedback.md`），本次只回退了拖动渲染那部分。

用户反馈新增反馈后拖动明显卡顿，且纸板点击听感不适。只读检查其当前房间：108 片、88 片归位、21 个组合、最大未归位组合为单片，序列化房间约 7.5KB、变更历史为有界 96 条。服务器服务约 126MiB，整机负载 0.06，5 秒消耗 29 个 CPU ticks；这些样本未显示服务器资源瓶颈。浏览器可列出当前标签页，但选择标签页超时，因此没有得到用户实际掉帧时的性能轨迹。

客户端原拖动路径每帧从桌面缓冲图恢复旧、新拼块区域，并再次绘制移动拼块；108 片模式还需重复原图裁切、阴影计算。暖光的坐标此前在每次请求绘制时更新，而不是每个实际帧一次。这些是本次消除的实际重复工作，不能据此断言已排除网络、设备或浏览器的其他卡顿因素。

## 改动

- `DragImage` 只缓存手里的拼块组，按显示缩放和 DPR 绘制一次，通过一个独立小 Canvas 的 CSS transform 移动。静止桌面在拿起时排除手里的拼块，普通指针帧不再复制背景像素或重绘拼图。
- 缓存最长保留到松手，限 300 万像素（约 12MB RGBA），普通单片远低于上限。超过上限使用原来的区域恢复渲染，不插值降低画质、不分配超大图层。组合、缩放、主题、提示变化会更新缓存；远处未显示的拼块也正确绘入组合缓存，移回视野不缺片。
- 真正的队友移动、加入和归位仍更新静止桌面；本人位置回声继续受原保护逻辑处理。抢块、吸附距离、保存和相机规则未改变。
- 暖光坐标移到已有 RAF 内，500 个绘制请求只更新一次坐标。暖光本身仍在 300ms 后销毁。
- 音效改为圆润起音、低频为主的软木轻触，削弱高频噪声及峰值；原有静音、音量、偏好和连续事件合并保留。

## 验证范围

使用原生 Skia Canvas 做相同 108 片、88 片归位、3200×2000 缓冲区的修改前后绘制对照，1 倍与 2.5 倍缩放各取 80 次：原绘制调用均值约 9.8/9.4ms，新调用约 0.023/0.020ms。新调用只移动小图层，因此这些数值不包括浏览器合成器工作，**不能当成用户设备的帧率**。为像素对照将小图层合成回桌面，平均通道差约 0.0032/0.0057（0–255），差异局限于缓存亚像素采样边缘。材料位于忽略的 `work/connection-perf-benchmark.*`，不上传生产。

自动回归覆盖 10800 次连续移动仅一次拼块绘制、零背景复制、缓存上限和释放、缩放/主题/提示更新、离开视野、多人更新与回声、300ms 暖光资源回收和每帧合并，以及音频峰值、起音、衰减和单声音限制。没有声称已在用户浏览器中复现或完成主观听感验收。
