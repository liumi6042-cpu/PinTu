# 在线拼图网站产品需求文档

版本：v0.1  
日期：2026年9月7日  
状态：待评审  
用途：确认产品定位、目标用户和首版范围，为下一版页面原型与详细需求提供依据。

## 1 产品定位与首版建议

建议打造一个可以独自放松、也能邀请朋友一起完成的在线拼图网站。用户打开网页就能理解怎么玩，拖动拼块时操作顺手，离开后能够继续上次进度。

首版建议围绕一条完整体验展开：**选一张喜欢的图 → 开始拼图 → 邀请朋友 → 自动保存 → 完成后再玩一张。**

### 已明确的方向

- 参考 jigsawpuzzles.io 的在线拼图与多人协作体验。
- 建设一个全新网站，改善现有网站给人的陈旧感。
- 当前先评审需求，确认方向后再细化设计和开发范围。

### 本版采用的工作假设

以下内容是讨论起点，尚未确认：

| 决策项 | 本版建议 | 对范围的影响 |
| --- | --- | --- |
| 核心用户 | 休闲玩家，以及想和朋友一起玩的用户 | 优先易用性、协作和续玩 |
| 产品气质 | 轻松、安静、重视图片与操作手感 | 游戏时减少弹窗与界面干扰 |
| 首发设备 | 桌面浏览器优先，同时支持手机与平板的基础玩法 | 手机首版限制复杂度，重点支持少片数 |
| 界面语言 | 先以简体中文评审，语言结构预留扩展 | 首发市场确定后再决定中文、英文或双语 |
| 首发协作 | 单人及私人邀请房间，暂定每房最多6人 | 多人同步从首版开始验证 |
| 运营方式 | 精选图库，先验证用户愿不愿意玩和再次回来 | 公开社区与收费功能后置 |

## 2 参考网站与新版改进方向

### 可确认的参考能力

| 信息来源 | 可确认的内容 | 对新版需求的启发 |
| --- | --- | --- |
| 官网玩法介绍 [1] | 公开游戏、私人邀请、单人及多人协作、继续未完成拼图 | 保留选图、开局、邀请、续玩的主流程 |
| 当前图库页面 [2] | 已有按视觉描述搜索图片的入口 | 新版应关注找图是否容易，而不把搜索本身当作独有卖点 |
| 官方更新日志 [3] | 记录了自定义图片、房主管理，以及同步、重连和拖拽相关改进 | 多人协作需要明确冲突处理与恢复规则 |
| 支持者权益页面 [4] | 提供去广告、更高分辨率及更大片数等权益 | 可作为后续付费方向的参考 |

本次浏览中，首页和图库页的广告占据了较多首屏空间，开始游戏与图片内容的视觉优先级有提升空间。[1][2] 这是本次访问的观察，不代表每位用户看到的布局完全相同。

本版依据公开页面和产品分析整理需求，尚未开展真实用户访谈，也未完成登录后的多人实测。下文的用户痛点是待验证假设；更新日志中的历史问题不应直接视为当前仍存在的问题。

### 将全新体验落实为具体改变

- **更容易开始：** 首页突出“立即开始”和“与朋友一起玩”，访客可以先体验单人拼图。
- **更专注于拼图：** 游戏画布占据主要空间，工具按需展开；拼图过程中不插入打断操作的广告。
- **更容易理解协作状态：** 明确谁在房间、拼块是否正被他人操作、是否正在保存或重连。
- **更适合触屏：** 区分拖拼块与移动画布，提供可点按的缩放和复位工具。
- **更有回来继续的理由：** 直接展示未完成记录，完成后推荐同主题或相近难度的图片。

## 3 目标用户与核心需求

首版重点服务前两类用户。其余人群作为后续扩展方向，避免同时承担竞技、社区和儿童产品的全部需求。

| 用户类型 | 典型场景 | 核心诉求 | 需求表达 | 优先级 |
| --- | --- | --- | --- | --- |
| 休闲玩家 | 独处或休息时玩一会儿 | 快速开始、没有压力、随时停下 | 我想不注册就试一局，下次打开还能继续 | 核心 |
| 好友协作玩家 | 朋友或伴侣远程一起玩 | 邀请简单、操作同步、共同完成 | 我想发一个链接，让朋友加入同一张拼图 | 核心 |
| 拼图爱好者 | 长时间完成较大拼图 | 高质量图片、整理工具、进度可靠 | 我想整理边缘块和已拼好的组合，不因刷新丢进度 | 次核心 |
| 自定义图片用户 | 用旅行照、宠物照制作拼图 | 制作方便、控制分享范围 | 我想把自己的照片做成只给朋友玩的拼图 | 后续 |
| 陌生人社交玩家 | 没有熟人在线时找人一起玩 | 有活跃房间、氛围友好 | 我想快速找到能加入且有人管理的房间 | 后续 |

上线前建议邀请5至8名目标用户完成“选图、开局、邀请、续玩”任务，观察他们是否需要解释、在哪里误操作。该人数是探索性测试建议，不用于推断市场规模。

## 4 用户流程与页面范围

### 单人首次体验

首页选择“立即开始” → 展示推荐图片与片数 → 进入拼图 → 按需查看简短操作提示 → 完成或离开 → 从“最近游玩”继续。

访客进度保存在当前浏览器；需要跨设备保存时再引导登录。登录过程完成后，应返回刚才的拼图，并保留已完成的进度。

### 好友一起玩

选图 → 登录并创建私人房间 → 复制邀请链接 → 好友打开链接并设置昵称 → 加入同一局 → 一起完成 → 房主选择下一张。

本版建议仅建房者需要登录，受邀好友可作为访客加入。这样能够确定房间归属，同时降低被邀请者的参与门槛。是否放开访客建房，列为待决策项。

### 中断后继续

退出页面或网络中断 → 显示保存或重连状态 → 再次打开记录或房间链接 → 恢复最新有效进度 → 继续游戏。

多人房间以共享进度为准：用户离开期间，其他人仍可继续拼图；回来时看到的是房间最新状态。

### 页面清单

| 页面或界面 | 主要内容 | 用户的主要动作 |
| --- | --- | --- |
| 首页 | 快速开始、精选图片、最近游玩、好友玩法说明 | 开始新拼图或继续旧拼图 |
| 图库 | 图片、分类、搜索、加载与空结果状态 | 找到想玩的图片 |
| 图片详情与开局设置 | 完整预览、作者来源、片数、单人或协作选项 | 确认图片和玩法并开始 |
| 游戏页 | 拼图画布、预览、整理工具、进度、成员、邀请、保存状态 | 完成拼图 |
| 我的拼图 | 进行中与已完成记录；访客显示本机记录 | 继续、重玩或整理记录 |
| 登录与设置 | 登录、昵称、声音、画布背景、基础帮助 | 建立账户和调整偏好 |
| 完成界面 | 完成图片、片数、参与者、用时说明、下一张 | 保存成果或再玩一局 |
| 运营后台 | 图库上下架、分类、图片来源、问题反馈 | 维护内容和处理问题 |

完成界面与开局设置可以使用弹层，首版不必分别建设独立页面。公开房间大厅在后续版本增加。

## 5 首版功能需求

优先级定义：**P0为首版必须完成，P1为核心体验稳定后增加，P2为探索方向。** 下表全部属于P0；片数、人数、性能和保存期限等数值仍是建议值。

| 编号 | 功能 | 用户可感知的要求 | 基本验收条件 |
| --- | --- | --- | --- |
| F01 | 快速开始与引导 | 访客可开始单人游戏；首次操作提示可跳过和重新打开 | 未登录也能从首页进入并实际放置拼块 |
| F02 | 图库与选图 | 支持分类、关键词搜索、完整图片预览和来源信息 | 查询无结果、图片加载失败时有明确提示及可用的下一步 |
| F03 | 片数与难度 | 提供约50、100、200、500片档位；实际片数在开局前显示 | 图片比例导致片数调整时，显示值与生成结果一致；首版默认不旋转 |
| F04 | 基础拼图操作 | 拖拽、正确吸附、相邻块组合移动、缩放、平移、视角复位 | 正确相邻块可在画布外组合；错误位置不会吸附；组合移动不散开 |
| F05 | 辅助与舒适度 | 原图预览、仅看边缘块、整理散块、背景及声音设置 | 工具不遮挡关键操作；过滤不丢块；整理不拆散已拼组合 |
| F06 | 私人房间与邀请 | 登录用户可建房；好友用链接和昵称加入；展示成员与人数 | 两个独立浏览器进入同一局；满员与失效链接都有清楚的反馈 |
| F07 | 实时协作 | 显示他人操作与拼块占用；同一拼块同时只由一人控制 | 两人同时抓同一块不会复制、丢失或产生不同结果 |
| F08 | 自动保存与恢复 | 访客本机保存，登录用户云端保存；显示保存和重连状态 | 正常刷新能恢复；断网后能回到最新共享状态；失败不显示“已保存” |
| F09 | 最近游玩与账户 | 进行中、已完成分开展示；登录后可在另一设备继续 | 同图不同局分别记录；本机存档转入账户不会覆盖其他存档 |
| F10 | 完成与再玩 | 全部正确放置后显示完成结果；可以重玩或选下一张 | 所有人只收到一次完成结果；新一局使用独立记录 |
| F11 | 运营与反馈 | 管理员维护图片、分类和来源；用户提交问题反馈 | 未上线图片不可开局；普通用户无法访问管理功能 |

### 拼图操作规则

1. 拼块只有与正确邻块或正确目标位置接近时才吸附。吸附阈值应随缩放适配，避免缩小后难以放置。
2. 正确连接的拼块形成组合，可整体拖动。已经固定到目标区域的拼块不再被随意拆散。
3. 原图预览、仅看边缘块、缩放、声音和背景均属于个人视图，不影响其他玩家。
4. “整理散块”会影响共享画布，因此多人局只允许房主执行；需要明确预告影响，且跳过别人正在拖动的拼块。
5. 首版不提供共享画布的通用撤销。后续若增加，只撤销能够确认未被他人接续操作的个人动作。
6. 手机上，单指拖拼块、双指移动或缩放画布；另提供缩放按钮和“回到拼图”入口，避免用户迷失在画布中。

### 房间与权限规则

- 私人房间不进入公开列表或站内搜索；持有有效邀请链接的人可以申请进入。页面应说明链接的访问作用。
- 房主可以关闭新成员加入、更新邀请链接、移出成员，并阻止被移出的同一身份立即重入。访客身份防绕过能力需在后续方案中确认，不能承诺绝对防止重入。
- 房主离开不结束游戏，也不自动把管理权交给陌生访客；现有成员可以继续拼图，房主返回后仍保留管理权。
- 普通成员不能换图、重置整局或修改房间人数限制。发起下一局由房主操作，并通知其他成员。
- 玩家断线、离开或长时间占用拼块时，应释放占用；恢复连接后先同步状态，再允许继续拖动。
- 暂定最多6人同时参与。最终人数上限通过原型性能与网络测试决定。

### 存档与计时规则

- 访客记录仅承诺当前浏览器内恢复，清理浏览器数据或更换设备可能无法找回；在存档入口说明这一范围。
- 登录用户的单人局及私人房间保存到云端。暂建议进行中记录至少保留90天，具体期限和到期提示在v0.2确认。
- 同步确认与持久保存应区分：只有确认已持久保存的状态才显示“已保存”。多人断网时暂停共享操作，避免离线改动覆盖他人进度。
- 同一账户在另一设备打开同一局时，沿用同一身份与同一存档；首版建议同一身份只保留一个可操作连接。
- 进度以已正确固定的拼块数除以总片数计算；画布外的组合尚不计入完成进度。
- 单人用时为有效操作会话累计时间；多人用时为至少一位玩家活跃时的房间累计时间。具体活跃判定阈值待细化，首版不做速度排名。

## 6 后续版本与商业化

### P1 核心体验稳定后增加

| 功能 | 用户价值 | 上线前置条件 |
| --- | --- | --- |
| 上传自己的图片 | 增加个性化与分享动机 | 文件大小、格式、裁剪、隐私、图片清理与内容处理规则明确；默认仅私人使用 |
| 公开房间大厅 | 没有熟人在线也能找到同伴 | 有可加入的真实房间，以及举报、封禁、房主管理和异常处理能力 |
| 收藏与每日精选 | 更方便找到下次想玩的图片 | 稳定的内容供给和基础回访数据 |
| 1000片及旋转模式 | 满足深度玩家 | 大片数性能、触屏可操作性和存档稳定性通过验证 |
| 简单表情与文字聊天 | 方便沟通分工 | 屏蔽、限频、举报与管理规则；文字聊天优先在私人房间试用 |
| 第二种语言 | 扩大可服务的人群 | 首发市场、内容语言、帮助与反馈支持方式明确 |

若用户最看重“把自己的照片做成拼图”，上传功能应调整到P0，同时减少其他首版内容。若最看重陌生人一起玩，公开大厅及其管理能力应整体进入P0。

### P2 探索方向

候选包括主题活动、成就、创作者投稿、AI生成图片、会员主题包及竞技玩法。是否开展由用户反馈与实际使用数据决定。原生App、小程序、语音聊天和开放作品社区不列入当前首版范围。

### 商业化建议

首版测试阶段建议保持基础体验免费，优先验证开始游戏、合作完成与回访。后续可测试会员图片包、更大片数、更多自定义存储或外观主题；付费项目应由实际使用频率和意愿验证。

如果采用广告，建议放在图库或完成后的非操作区域，并控制频次。广告模式、会员价格、支付渠道与上线地区尚未确认，本版不设收入预测。

## 7 质量要求与首版验收

### 建议的质量目标

以下是待原型验证的目标，不是参考网站的实测数据，也不是已经做出的性能承诺。

| 项目 | 建议目标与测试口径 |
| --- | --- |
| 开始速度 | 在约定的代表性桌面设备、20 Mbps下行、100 ms往返延迟环境中，从点击开始至500片可拖动的P95不超过5秒；冷缓存计入图片加载 |
| 拖拽流畅度 | 在同一代表性设备的500片6人局中，连续操作5分钟，拖拽期间至少95%的1秒窗口达到50 FPS；手机以200片、30 FPS作为初始目标 |
| 多人同步 | 在约定网络条件下，另一客户端看到落块最终结果的延迟P95不超过300 ms；先保证结果一致，再优化动画 |
| 保存与恢复 | 已显示“已保存”的状态在刷新及服务重启恢复测试后仍存在；未保存状态有提示，重连不产生重复拼块 |
| 兼容性 | 发布时桌面Chrome、Edge、Firefox、Safari近两个主要版本完成核心流程；手机Safari与Chrome验证少片数触屏流程 |
| 可用性 | 常用图标有文字解释或标签；焦点可见；状态不只靠颜色表达；支持关闭动效与声音；键盘拼图的覆盖范围另行评估 |
| 内容与访问 | 图库图片有可追溯来源及使用依据；私人房间内容不进入公开索引；管理功能与私有资源执行权限检查 |

具体设备型号、浏览器版本、测量方法和预计同时在线规模需在v0.2锁定。全站承载能力尚不能仅由“每房6人”推出。

### 必须通过的典型场景

1. 新用户不登录，完成一局少片数拼图并找到下一局入口。
2. 两个独立客户端在同一私人房间分别拖动拼块，最终画布一致；继续验证到人数上限。
3. 两人同时抓取同一拼块或组合，结果唯一；掉线后该拼块可以继续被操作。
4. 拖动中断网、刷新、退出再进入，不出现缺块、重复块或存档被旧状态覆盖。
5. 房间已满、链接失效、房主离开、成员被移出时，都有明确状态和可用操作。
6. 图片加载失败、保存失败、没有搜索结果、没有历史记录时，页面不会停在无说明的空白状态。
7. 最后一块由任一成员放下后，全员进度变为100%，完成记录只生成一次。
8. 手机缩放与拖块不误触浏览器页面缩放，常用工具可操作，图片和按钮不溢出屏幕。

## 8 上线后的验证指标

建议以“每周完成至少一局的独立用户数”观察产品是否持续带来价值，同时分别分析单人和多人玩法。以下指标先建立基线，再设置增长目标，不预填未经验证的转化率。

| 指标 | 定义 | 用于判断 |
| --- | --- | --- |
| 开局转化率 | 发起至少一局游戏的独立访客数 ÷ 访问首页的独立访客数 | 首页和选图流程是否容易理解 |
| 首局有效体验率 | 首次开局后成功放置至少5片的独立用户数 ÷ 首次开局用户数 | 加载和初次操作是否顺利 |
| 邀请加入率 | 有受邀成员成功加入的私人房间数 ÷ 生成过邀请链接的私人房间数 | 邀请流程是否有效；不能把生成链接等同于已分享 |
| 七日完成率 | 开局后7天内完成的局数 ÷ 同期开局且已满7天观察期的局数 | 难度与续玩是否合理；按片数和玩法分组 |
| D7留存率 | 首次游玩后第7天再次有效游玩的用户数 ÷ 该首玩日用户数 | 是否形成回访；统计时区统一约定 |
| 质量指标 | 开局失败率、重连成功率、保存失败率、拼块异常反馈量 | 是否应优先修复基础体验 |

访客跨设备不能稳定去重，应和登录用户分别报告。建议只采集必要的游戏事件及匿名标识，不把私人图片、邀请密钥或聊天内容放入分析事件。

## 9 本轮需要确认的事项

优先确认前三项，即可开展下一轮细化；其余项目可以在页面方案中继续讨论。

| 编号 | 待决定的问题 | 本版建议 | 改变后会影响什么 |
| --- | --- | --- | --- |
| D01 | 最希望服务谁：独自放松、好友协作还是陌生人社交 | 休闲单人加好友协作 | 首页重点、多人范围、社区管理投入 |
| D02 | 面向国内用户、海外用户还是两者 | 暂不锁定市场，以中文稿评审 | 语言、登录方式、部署区域、内容与商业化 |
| D03 | 首版最重要的区别是什么 | 现代视觉、顺手操作、可靠协作 | 设计与研发投入顺序 |
| D04 | 手机是否必须和电脑一样完整 | 手机先支持基础玩法和少片数 | 交互复杂度与验收范围 |
| D05 | 上传照片和公开大厅是否必须首发 | 两项均先列P1 | 内容处理、资源成本与房间管理 |
| D06 | 是否接受建房者登录、好友免注册加入 | 接受 | 建房门槛、房间归属与恢复方式 |
| D07 | 偏治愈放松还是挑战竞技 | 治愈放松，首版不做排名 | 计时、提示、画面风格与增长设计 |
| D08 | 是否计划首发收费，以及有哪些预算或日期限制 | 先免费验证；预算与日期待提供 | 功能取舍、服务成本与发布计划 |

确认方向后，v0.2将补齐：首页、图库和游戏页线框；登录及建房方式；上传和公开大厅的去留；保存期限、房间生命周期和异常规则；目标设备与容量；按实际团队资源安排的开发任务和里程碑。
