## 共用客户端背景音乐与队友声音补正（2026-10-19，本地候选）

**最新决定：用户取消背景音乐，留待以后。** 三版合成素材保留作本地候选，当前游戏不选曲、不显示音乐调节或试听入口，新 TapTap 包不含 MP3；只保留拼合音效音量记忆和队友漏声修复。该客户端已上传 TapTap 开发自测 **329733**，未公开发布；原先本节的音乐设置、构建和试听记录是历史候选状态。正式 Web 与微信平台包未随此轮上传更新。

用户选择「轻柔钢琴＋少量音乐盒」方向。原创合成小样《午后小窗》为 72 BPM、16 小节、约 53.33 秒，无鼓点；音符编排、模态合成源码、母带和来源清单位于 `content/music/cozy-window`，没有使用外部录音或采样，也未调用付费音乐服务。运行用 MP3 为 427,200 字节、64kbps，母带为 44.1kHz 双声道 WAV。曲目可循环，原生 MP3 循环仍可能有编码填充间隔，不能称为已验证绝对无缝。

试听反馈为「不太行，要略微轻快一点」。第二版独立保存为 `cozy-window-v2.mp3`（357,696 字节，约 44.65 秒）与 `manifest-v2.json`，使用 `compose.py --light` 重现：速度改为 86 BPM，缩短琴音尾音，抬高低音音区，改写轻巧跳跃的旋律与分解和弦，保留稀疏音乐盒、无鼓点和原有整体响度。原版素材与游戏包不覆盖；第二版仅供试听，尚未确认、接入运行包或上线。

随后用户希望「舒缓一点，带一点节奏感」。第三版「轻摇版」使用 `compose.py --relaxed-pulse` 重现，独立保存为 `cozy-window-v3.mp3`（394,368 字节，约 49.23 秒）与 `manifest-v3.json`：78 BPM，以稳定的两拍低音和弱拍分解和弦形成轻律动，主旋律减少跳跃与音符密度，柔化起音，音乐盒减少至四处点缀，不加鼓轨。母带峰值约 −9.94 dBFS，无削波；仍只供试听，未替换游戏包或上线。

设置新增「声音」：背景音乐与拼合音效分别使用加减按钮、十段点选音量轨和百分比。背景音乐默认 0%，拼合音效保留原基准音量；「试听音乐」在静音时设为 25%。偏好只写设备本地存储，独立保存，不改玩家身份、钱包、进度或房间。Web/TapTap 使用包内 HTMLAudio，微信使用原生 InnerAudioContext；后台和激励广告分别暂停，恢复时仍遵循当前音量和前台状态，销毁释放音频。播放需要用户手势解锁。

队友成功反馈沿用较轻的拼块组轮廓和拼合声音，本人另有火花与经验回执文字。本次补正自己的动作回执先携带队友成功变化时的漏声，排除本人的待确认拼块组，避免双响；WebSocket 和 HTTP 回退均处理。普通移动、重复快照、首次载入及重连快照仍不重播队友成功声音。

聚焦验证：队友反馈 4 项、音频平台生命周期 6 项、偏好持久化与异常容错 2 项通过；源码类型检查通过。隔离 TapTap/微信正式模式构建位于 `work/background-music-20261019/build-v1`；微信主包 3,986,540 字节，小于 4 MiB。MP3 已列入共享包，后续不能沿用仅替换 `game.js` 的旧打包方式。网关两条音频静态路径已补 `audio/mpeg`，本地读取核对文件大小与哈希通过，证据为同目录 `audio-serving.json`。

Chrome 原生播放器已实际播放且进度前进，无解码错误。此轮游戏页的浏览器截图超时，设置布局另用真实 Stage/GameApp 的离线 Canvas 渲染复核；原生手机/TapTap/微信实际听感仍需试听。图库检查仍报既有 `cel-coastal-family-v1` 衍生图片记录无效，本次没有改动图库来消除此项告警。

本节代码、素材和构建均为本地候选，`listeningApproved=false`、`published=false`；没有部署服务器、上传新自测包或发布后台内容。线上既有普通房间长连接版本与此轮音乐候选应分别判断，不能把本地构建当作已上线。

## 共用 Canvas 客户端（2026-10-14）

Web 与小游戏共用的 `mobile/puzzle-board.ts` 已恢复移动版原有的反馈：成功拼合或单片归位后出现双层暖金轮廓，本人另有四颗短促的小亮点；服务器回执确实记入经验时，显示对应的 `+N XP`。时长沿用 500ms，最多同时三组。队友仅显示较弱轮廓，不显示本人的经验文字；初次载入、重连、普通移动与重复快照不重播成功动画。

此次问题来自共享 Canvas 迁移只保留单层描边，遗漏旧 `ConnectionGlowRenderer` 的亮点及经验回执展示；奖励计算仍在服务器，未改经验或金币数值。待确认的本人落片单独记录，因此服务器回包前后都不会误当作队友落片。真实回执按请求 ID 去重；即使轮询比落片确认先到，也只显示一次经验。

轮廓跟随实际拼块组和视角，亮点、文字保持屏幕尺寸；隐藏页面和退出房间清理动画。浏览器选择“减少动态效果”时沿用 170ms 静态轮廓，不播放亮点。针对验证覆盖真实确认、轮询竞态、缩放平移、隐藏状态和重复回执；未改变拖拽、吸附、光标持久显示或多人房间协议。

## 原版 Web 接缝反馈与声音

正确相邻的拼块连成一组时，新接缝出现淡暖光，300ms 内消退。落入正确位置但没有新接缝时，只提供可选的声音反馈。原有吸附距离、拼块位置、计时和贡献规则保持不变。

暖光用一次绘制的透明 Canvas 小图层和 CSS 淡出实现；同时最多 3 个图层，每层最多 32 段接缝，图像最长边不超过约 768 像素。拼图视角移动只更新图层位置，不创建动画重绘循环。到时、切后台和离开游戏均释放图层；减少动态效果时用短暂的静态细线替代淡入淡出。普通多人拖动同步不扫描新接缝。

用户最终选择 C 款「清脆双击」。使用此前试听的 4 个原始 48kHz 单声道 PCM16 WAV，每段 98ms，两个短促卡合音头，无长尾。音效为本项目原创程序合成，不加载外部录音。原件、生成脚本及 SHA-256 位于 `content/sound-effects/crisp-double-click`；`node scripts/prepare-click-audio.mjs` 验证哈希并将音频 PCM 打包到 `lib/double-click-data.ts`。音频启用时解包为缓存 AudioBuffer，使用原始 48kHz 采样率，让浏览器适配设备；落片时没有下载或解码工作。测试逐个采样核对试听与运行 PCM 相同。

同一时刻只保留 1 个声音，180ms 内重复成功事件合并，不排队播放。多人声音分为本人落片和队友落片：本人只在成功服务器响应后发声；队友只在已连接期间收到新的成功拼合拓扑时发声。正在等待确认的本人拼块受保护，不会被轮询误判为队友声音；失败操作、重复轮询和断线重连快照不发声。

右下角喇叭打开设置，含拼合音效总开关、队友拼合音效开关、0–100% 音量及试听。新访客两个开关默认开启、音量 25%；旧访客明确关闭过总开关时继续保持关闭。浏览器保存开关和音量并同步到同源标签页。音频上下文只在玩家手势后恢复，浏览器禁止自动播放时不会自行出声，音频不可用也不阻断游戏。修改偏好不会重建拼图或多人连接。

验证使用 `tests/connection-feedback.test.mjs`、`tests/connection-client.test.mjs`、`tests/puzzle-table-render.test.mjs`、`tests/room-sync.test.mjs`、`tests/multiplayer-organize.test.mjs`，覆盖新接缝与重复同步、2000 片上限、资源回收、音频峰值与衰减、偏好、单声音合并、服务器确认竞态、拖动局部重绘及多人整理。另运行 TypeScript 检查、正式构建和运行包 HTTP/资源校验。本次浏览器控制服务超时，尚未完成浏览器视觉和实际听感验收。
