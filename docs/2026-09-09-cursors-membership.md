# 队友鼠标与会员创建入口

## 行为

多人桌面为其他玩家显示彩色鼠标和昵称。世界坐标转换到观看者自己的镜头坐标，所以不同缩放和拖动画布不会指错位置。覆盖层最多 7 个 DOM 指针节点，独立于拼图 Canvas；平滑移动支持减少动态效果。离开画布、后台、暂停发送隐藏；静止后最后 3 秒淡出，10 秒失效。昵称颜色从房间真实成员读取，客户端不能替换别人的身份。

鼠标每客户端最多每 200ms 交换一次，快速事件合并为最新坐标，单次请求不排队堆积。接口只读取房间鉴权元数据，临时位置写入独立 puzzle_room_cursors 小表，绝不调用拼块 action、变更房间 revision、续期房间或计成绩。序号与隐藏记录防止同一客户端迟到请求令鼠标重新出现。鉴权沿用原成员票据及账号/游客 Cookie 绑定。

创建多人房间改为会员权益。本次按本地未接支付的现状，暂时锁定所有个人创建入口并显示“订阅即将开放”，不收款，也没有测试会员前端开关。限制覆盖 private/public 和不带 visibility 的旧匿名邀请创建请求；前端传入 isMember/subscriptionActive 无效。免费单人局、公开大厅预设桌、加入或继续旧房间不受限制。真实订阅开通仍需后续接入支付和服务器权益核验，本次没有声称实现收款。

## 验证

- TypeScript 与本地生产构建通过；新增 0002_room_cursors.sql 已本地执行，仅新建临时表及过期索引，旧房间与原有进度未改动。
- 30 项非浏览器测试通过，覆盖坐标、合法输入、序号、事件节流、会员门槛，以及原有多人/缓存/账号/双语行为。
- 2 项真实 HTTP 新测试通过：生产接口拒绝非会员与伪造会员字段创建，允许单人及旧邀请加入；成员 Cookie 绑定、离开隐藏；8 人鼠标通道同时运行 2000 片拖动并保持进度收敛。
- 最终 8 人同时测试中的 86 次鼠标请求全部成功，P95 约 342ms。这个数字来自本机 HTTP 并发测试，不是浏览器帧率或公网容量承诺。
- 另有 3 项原有真实 HTTP 集成回归通过：账号及私人/单人权限与用时榜、游客与可选登录后继续、真实 RoomClient 同步与重连。
- 原有多人回归测试的房间创建改为通过 tests/room-http-fixture.mjs 向本地数据库预置专属夹具；生产接口不提供测试绕过。该夹具只允许 localhost/127.0.0.1，不修改用户已有房间。
- 用户未要求浏览器测试，本次未做 DOM/截图/模拟点按验证。本地服务器保留运行，未发布公网。

## 局域网 HTTP 兼容修复

朋友通过局域网 HTTP 地址加入时，浏览器不提供仅限安全上下文的 crypto.randomUUID，导致 CursorClient 初始化抛错，连带多人页面无法进入。鼠标会话 ID 改用 crypto.getRandomValues 生成 16 字节并编码为 32 位十六进制；服务器原有校验、成员票据、房间与进度不变。

新增回归测试移除全局 crypto 的 randomUUID 与 subtle，仅保留 getRandomValues，验证两个鼠标客户端可以创建不同 ID、发送有效坐标并以同一 ID 发出递增序号的隐藏消息。测试在修复前复现用户报错，修复后通过；鼠标相关共 5 项测试、TypeScript 检查与本地生产构建通过。更新后本机及局域网房间页面 HTTP 200，局域网提供的新版 puzzle-app 脚本已使用 getRandomValues，无 randomUUID 调用。本地服务器继续运行。
