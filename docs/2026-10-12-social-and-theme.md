# 好友、聊天举报与浅深主题

日期：2026-10-12。依据已确认的[概念图](concepts/2026-10-12-themes-friends-chat/README.md)开发。用户追加确认：**公开房间只能发预设内容，不能自定义发言。**

## 入口与交互

- 点击头像进入设置，可切换浅色、深色；即时生效并在本设备保存。沿用 B2 像素边框的整数像素绘制，场景图片和拼图原画保持原色。
- 大厅和设置提供“好友与消息”，显示未读消息及申请数量。每位当前游客获得服务端生成的 9 位玩家编号。
- 好友面板分“好友 / 消息 / 申请”，支持编号搜索、发送申请、接受或忽略、同桌添加、删除和屏蔽。好友显示昵称、等级与在线状态，接受后双方建立关系。
- 私聊支持多行文字与房间邀请卡片；接收方点击卡片进入对应房间。消息可长按操作，未读随实际打开会话消除。
- 点击游戏顶部在线人数展开房间交流；竖屏使用下方抽屉，横屏使用右侧面板，关闭后恢复拼图区。
- 公开交流只有“协作 / 鼓励 / 表情”预设按钮。客户端没有输入框；服务端校验预设编号，也拒绝旧客户端传入任意文字。兼容旧接口仅接受与预设完全一致的文字。
- 公开消息和私聊都支持举报、屏蔽，举报预览引用实际消息。原因包括骚扰、广告、不当内容及其他；屏蔽会隐藏对方公开消息、解除双方好友关系并禁止后续私聊。

## 消息与奖励规则

私聊不采用公开区短句限制；单条技术上限为 2,000 个 Unicode 字符，发送间隔 3 秒。屏蔽词在服务端检查，规范化大小写、空白和标点后匹配；可通过服务器配置补充词库。基础词库不是完整内容审核服务。

添加好友、接受申请和发私聊本身不发放邀请奖励。已有“分享邀请每日最多 3 次、每次 20 体力＋10 经验”与“首次有效加入并完成 3 次有效拼合后发补满体力包、每日最多 3 位”规则保持原样。新好友同房实际参与拼合可推进好友协作任务，仍需最近参与且在线，不凭接受申请增加进度。

## 数据与接口

沿用现有身份验证与 SQLite，新增玩家编号、好友申请、双方关系、屏蔽、私聊消息、阅读位置、限流记录及举报记录。玩家编号不暴露登录凭证。操作支持请求重放，非好友不能私聊，房间邀请仍校验当前房间凭证。

主要接口集中在 `/api/mobile/social`，包括玩家查询、申请与处理、会话、消息阅读、好友删除、屏蔽和举报；房间聊天继续使用原房间聊天接口。服务端限流覆盖编号查询、申请与发送，重启后仍保留。

举报写入 `mobile_chat_reports`，服务端保存消息原文证据、作者、举报人、会话及原因，初始状态 `pending`；重复提交不会新增一份举报。提交不自动处罚。**举报审核管理页面本轮尚未制作**，后续管理后台需要接入待处理队列。

玩家编号与好友、消息绑定现有游客身份；本设备身份保留时编号稳定。**跨设备登录与账号合并尚未接入**，不能承诺换手机或清除本地身份后找回原好友和进度。
