# 本地内容后台实施记录

设计于 2026-10-12 经用户“开始吧”确认，详见 ../../design/2026-10-12-content-admin-design.md。

实现采用 Node.js 24 自带 HTTP、密码派生和 SQLite，无额外依赖。新增内容限于 D:/chat/拼图/content-admin，不修改现有游戏、玩家数据、部署配置或 CDN。

实施顺序：

1. 读取两项目目录与来源记录，建立共用素材视图和独立目标基线。
2. 保存完整草稿、画风/题材与目标配置，保护稳定 ID 和 revision。
3. 完成管理员初始化、会话、同源/CSRF 检查与二次密码校验。
4. 连接素材、图包、图鉴表单与差异/版本页面。
5. 通过聚焦写入、安全、兼容与版本验证，交付本地地址和使用说明。

版本与草稿存于独立 work/admin.sqlite。发布候选为私有下载的 JSON 文件集合，由现有项目发布流程审阅接入；规划快照可以保存受阻变更，可运行候选不能跳过阻断。

## 2026-10-12 完成交付

本地入口为 http://127.0.0.1:3214，管理员尚未初始化，留给用户首次访问设置。start.ps1 启动后台进程；stop.ps1 停止本工具记录的实例。后台只监听本机，不自动启动云服务或发布生产内容。

三组聚焦验证分别通过：HTTP 7 项、数据与兼容 11 项、来源合并 3 项，共 21 项。HTTP 验证核对前后三份真实游戏目录 SHA 相同，测试使用独立临时数据库并已清理。

验证覆盖异常 CSRF、非法字段与引用、revision 冲突、来源 fingerprint 变化、历史 ID 缺失的持久保护、成功候选/快照、旧包成员/价格/奖励阻断、再次验密、版本恢复、来源三方合并排序及会话限流。候选生成调用两个项目的完整原件/授权/审核/衍生校验，小游戏计划资源为 268 个 WebP、65,083,688 字节。

浏览器主流程已走通：登录临时管理员、素材详情编辑画风与题材标签、保存草稿、查看差异与兼容提示、保存完整规划快照、查看图包封面与顺序。页面无运行错误。临时管理员与浏览数据已随隔离验证目录清理，正式 work 数据仅含初始内容基线，不含测试账号或测试标签。

界面预览保存在 content-admin-preview.png，随后台界面更新；截图来自隔离验证实例，测试内容和选择不写入用户的正式草稿。

首期管理已登记素材；新图片仍按原项目审核/压缩流程入库再重新导入。画风/题材是管理配置，游戏展示新分组、独立封面、图包上下架、独立图鉴及权益重组需要后续目标适配，发布页会明确阻断，不用新字段伪装已生效。

## 2026-10-12 使用反馈修正

“发布与版本”改为“检查与备份”，以保存草稿、检查改动、保存版本备份三步说明流程；准备游戏更新文件放在独立折叠区，历史版本可恢复为新草稿，游戏变更需原发布流程实际应用。

多选操作栏改为底部固定显示，新增当前目标批量归档/恢复/图库隐藏/显示及撤销；保留历史 ID、来源、另一端配置、图包价格与权益。所有状态改变只进入当前草稿，关联图包和图鉴在确认弹窗展示，发布兼容检查继续生效。6 项新增批量逻辑测试通过，并在隔离后台确认多选栏、归档确认、撤销和新版三步流程可用。
