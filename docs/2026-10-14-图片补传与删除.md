# 图片补传、删除与玩家记录

## 本轮状态

2026-10-14 已完成双端部署和独立核验。首次只读核查时缺失的 53 张图片、159 个游戏资源文件现已全部交付；两端运行图库均为 187 张，后台发布预览显示 187 张可进入游戏、没有待交付提示。`待上传` 文件夹的 7 张图片与已有素材相同，没有重复导入。

“图片已交付”和“玩家能够看到”是两步：完成资源交付后，图片仍按已保存的相册归属、相册显隐和每日安排展示。程序或图片上传不等于发布后台设置；管理员确认“提交到双端”后，正式游戏才采用已保存配置。

## 如何删除或恢复

| 位置 | 操作 |
| --- | --- |
| 全部图片或未分配区域 | 勾选图片，点击“删除所选图片” |
| 图片详情 | 点击“删除图片” |
| 相册内部 | 勾选图片，点击“删除所选” |
| 全部图片 → 回收站，或更多 → 图片回收站 | 单张恢复，或多选后“恢复所选图片” |

删除前的确认窗会列出受影响相册、购买包及每日首发安排。确认后先修改当前编辑内容；点击顶部“保存”，再通过“提交到双端”检查并确认提交，玩家端才会更新。恢复也使用同样流程。

删除采用回收站方式：图片移出相册，失效封面自动换成剩余首张；普通列表、选图器和未来的每日选图不再显示它。原件、稳定图片 ID、旧房间引用和玩家已有记录继续保留，因此不会释放服务器图片占用空间。恢复后可重新分配相册，不自动恢复普通相册原归属。

未出场的每日首发安排随删除取消。已确认出场的事实及锁定计划保留，删除期间停止自动收录；当天已经选中的每日图片仍保留到当天结束。恢复已出场但尚未收录的图片后，原有收录安排会继续。

## 移动相册对记录的影响

完成记录以玩家和稳定图片 ID 对应。移动图片只改变相册成员，不改变图片 ID，不会删除该图的完成记录、贡献或已经领取的奖励。相册当前显示的完成数量与完成比例会按新成员计算；图片所在购买包或展示范围也会随归属变化。

双端购买时均按图片保存使用权快照。购买时包含的图片即使移到其他相册，玩家仍可使用，无需重新购买这张图片；不会因此同时解锁目标相册的其他图片。后来临时追加到已购相册、随后又移出的图片，不属于当初购买的逐图快照范围。

## 原 Web 历史记录衔接

首次核查发现旧记录已保存在服务器，但新界面的收藏数据并未完整收录：共有 355 组旧“玩家—图片”完成对应关系，其中 354 组当时尚未进入新收藏。不能将“原数据库保留”表述成“新界面已全部同步”。此缺口需要单独补齐历史映射，不能靠移动相册、删除恢复或重新上传图片解决；补齐时应保留原完成事实，不重复发放金币、碎片或相册奖励。

## 实现与验证边界

删除、恢复和移相册均复用当前内容的保存版本检查；任务奖励、成长与体力使用各自的保存入口。删除功能的 5 项定向测试及原每日功能 6 项测试已通过；后台已重启启用，实际浏览器确认了批量删除、详情删除、确认说明、回收站及发布预览，未实际删除图片。用户已保存文档、任务奖励和成长设置在操作前后摘要完全一致。
