# Git 和最小运行包

网站代码仓库位于 `puzzle-play`，沿用已有 Git 历史。设计参考和生成原件保留在本地；Git 用于保存网站源码、登记的图片与版本，不承担线上数据库备份。

## 后续发布规则

1. 完成改动和本地检查，提交 Git。
2. 在构建机运行 `npm run release`，得到 `releases/latest.tar.gz`、`latest.json` 与 `latest.sha256`。命令自动在临时目录解压、启动并检查页面、全部图片与文件哈希，通过后才标记可上传。
3. 使用 `npm run release:upload -- --host webhosting-main`，仅传送这个经过哈希及 Git 版本校验的最新运行包。可加 `--dry-run` 查看目标和体积，不连接服务器。
4. 运维将包解压到新的独立运行目录、验证哈希及健康检查后切换服务。数据库和环境配置仍使用服务器现有共享位置；原有 systemd/nginx 配置不随普通页面发布重复上传。
5. 本次若新增或修改公共搜索页面，在构建机使用 `npm run search:notify -- --submit <变更的正式网址...>` 通知 IndexNow；先完成上线验证，只提交变更页面，不在上传运行包或玩家操作时触发。见 [搜索引擎接入](search-engines.md)。

上传命令只传文件，不自动部署、不删除服务器文件、不停止服务。2026-09-11 用户查看占用后另行授权服务器清理，已删除冗余资源和下载缓存，未上传新包或切换代码，详见 [清理记录](server-storage-cleanup-20260911.md)。服务器安装目录和当前版本每次先核对；不能继续依赖老 source/node_modules 或图片软链接。

普通发布使用新的独立目录，不复制旧运行目录再叠加，也不恢复重复 public、原始 PNG 或下载缓存。发布验证后保留当前与一个已验证的回退版本，避免旧版本无限累积；数据库与备份的保留规则独立于代码版本，不能随旧版本一并删除。

## 包含什么

- 最新编译完成的服务端/客户端文件，以及 standalone 明确收集的运行依赖。
- 网站实际使用的 favicon、首屏 WebP 和每张已发布/归档图片的无损游玩 WebP、缩略 WebP。归档画面的旧存档仍可继续。
- 不可改写的 SQL 迁移、五个运行/备份辅助模块；内含逐文件 SHA-256 的 `release.json`。

## 不包含什么

- 开发源码目录、项目完整 node_modules、Git 历史、原始 PNG、生成提示词、设计参考、测试与历史部署资料。
- `.env`、站点密钥、数据库、玩家上传数据、账号、备份、临时文件、旧打包文件和重复的 public 副本。
- nginx/systemd 配置默认不进应用包；需要修改基础设施时单独审阅并处理对应配置，不混进日常发布。

原始图片与来源记录仍保存在源码仓库中，不删除。新前端资源必须加入 `config/runtime-assets.json`；拼图 WebP 由目录自动取得。打包缺少必需文件或发现本机原生二进制时直接失败；这时应改用目标 Linux 构建环境，不能把 Windows 原生依赖发送到 Linux。构建与运行建议使用相同 Node 主版本（当前使用 Node 24）。

## 本地文件

`releases` 只保留一个 latest 包及其校验资料，每次替换上次本地构建包，且被 Git 忽略。构建在系统临时目录的独立源码副本中完成，结果暂存 `work/release-build`，打包后清理；不会覆盖本地试玩 `dist`，也不会读入本地私有配置。`--allow-dirty` 仅供本地验证，生成的包会标记 dirty，上传脚本拒绝发送。源代码或 Git 版本在构建后有变动，也必须重新构建。

`.wrangler/state`、`work/backups`、玩家图片、原始画面、来源记录和私有配置始终保留。旧文档中「上传源码，在生产服务器构建并逐次复制整套目录」的步骤已停用，以本文和 AGENTS.md 为准。
